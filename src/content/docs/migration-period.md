# 移行期間中の運用（旧システム @Suite との併用）

> ⚠️ **このページは移行期間中（2026年11月時点）の運用を説明しています。** 移行が完了したら内容を更新します。

新システムへの切り替え期間中は、旧システム（@Suite）の伝票が **毎晩、自動で新システムへ転記** されています。このため、画面の表示が @Suite と少し違って見えることがあります。ここでは、その理由と見方をまとめます。

---

## いまの仕組み

| 項目 | 内容 |
|------|------|
| 転記の向き | **@Suite → 新システム の一方向** です。新システムから @Suite へは書き戻しません |
| 転記のタイミング | 毎晩の自動処理（夜に開始）です。@Suite の変更は転記が終わってから新システムに表示されます |
| 転記されるもの | 伝票・明細・配送・入金の情報。出荷や返却の進み具合も @Suite の状態に合わせて更新されます。注文方法は、@Suite から読み取れた場合に転記します |
| 転記した伝票の金額 | 移行期間中に @Suite から転記した伝票の金額は、@Suite を確認してください |

> **💡 新システムで直接作った伝票:** 新システムの管理画面やオンラインストアで作った伝票は @Suite には転記されません。**@Suite 側の在庫・伝票には表示されない** ので、@Suite だけで在庫を確認している場合は、新システムの [商品予約状況照会](/product-reservation-inquiry/) もあわせて確認してください。

---

## 画面の見方で迷いやすい点

### ピッキング・出荷登録の画面に「処理漏れの可能性」の警告が出る

[ピッキング・出荷登録](/picking-delivery/) には、貸出開始日が過ぎても未ピッキングの伝票があると警告が表示されます。移行期間中は、**実際には処理漏れではない伝票** が一覧に残ることがあります。主な理由は次の3つです。

| 理由 | 説明 |
|------|------|
| @Suite で削除（取消）された伝票 | @Suite での削除は毎晩の転記では反映されません。全項目が0円で、入金・請求や在庫の取り置きが残っていないと確認できた伝票は、別の一括処理で取り消します。それ以外は個別に確認します |
| 社内確保の伝票 | 出荷しない社内利用の伝票です。期間が過ぎると毎日早朝の自動処理で完了になります（[社内確保の伝票](/internal-hold/) を参照） |
| 転記待ちの伝票 | 前日夜以降に @Suite で操作した分は、その日の夜の転記まで反映されません |

> **💡 判断のしかた:** 警告の件数だけでは、業務の遅れかどうかは判断できません。貸出開始日の古い伝票が並んでいる場合は、@Suite 側で同じ伝票の状態を確認してください。

### @Suite で削除した伝票が、新システムに残っている

@Suite で削除（取消）された伝票は、上の表の条件を満たした場合に別の一括処理で取り消します。

> **⚠️ 新システムの「伝票キャンセル」で消さないでください:** 新システムで伝票をキャンセルすると、キャンセル料の計算やお客様への通知が動く場合があります。@Suite で削除済みの伝票は、まとめて取消に反映する運用に任せてください。急ぎで対応が必要な場合は、開発担当へご連絡ください。

### 社内確保の伝票を @Suite で延長した

@Suite から転記した社内確保の伝票は、期間が過ぎると新システムで自動的に完了になります（2026年11月から）。完了にしたあとで @Suite 側で期間を延長した場合は、新システムが自動では更新できないため、**手動確認の対象** になります。期間が終わる前に延長した場合は、この扱いにはなりません。

## よくある質問

### 新システムと @Suite で金額や状態が違います。どちらが正しいですか？

@Suite から転記した伝票は、移行期間中は @Suite の金額と状態を確認してください。翌日も新システムの表示が揃わない場合は、開発担当へご連絡ください。

:::dev
- 転記: `scripts/legacy-suite-monitor.ts`（夜間の LaunchAgent・`run-daily-sync.sh`）。@Suite への書き込みリクエストは network guard が禁止（read-only）
- @Suite 側削除の検知: `pending-removals.json` に蓄積。取消型（全項目0円・入金/請求/Shopify連携なし）と機械判定できたものだけ `scripts/converge-legacy-removals-2987.ts` で CANCELLED に収束（手順書 `.claude/knowledge/manuals/24-legacy-removal-convergence.md`）
- 社内確保の転記伝票の期限切れ自動完了: Render 環境変数 `INTERNAL_HOLD_EXPIRE_LEGACY=on`（2026-11-05 設定）。延長されたものは pending-stuck（手動確認）
