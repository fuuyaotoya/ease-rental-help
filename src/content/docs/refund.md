## 概要

支払済みの伝票に対して、**払い過ぎ・一部キャンセル・誤請求**などの理由で顧客にお金を返す操作です。伝票編集画面の「料金・支払」セクションから行います。商品削除・減額後に**「返金可能額」**が表示されたカード伝票は、下記の「過払い返金」を使います。それ以外は **「返金を記録」** を使います。

### ⚠️ 返金は必ずEASE管理画面から行ってください（7/23定例 B項）

:::warning
**Shopify admin で直接返金しないでください。** EASE 側に記録が残らず、顧客への請求表示と実際の返金がズレます。
:::

- **クレカ返金**: 「返金を記録」で「Shopify(クレカ)」を選んで実行すると、クレジットカードへ返金されます。Shopify 管理画面を開く必要はありません
- **現金・振込返金**: お客様へ返金した後、EASE に記録します
- **Shopify 管理画面で直接返金してしまった場合**: 「返金を記録」で返金方法を必ず **「現金」**（記録のみ）にして実績を記録してください。**「Shopify(クレカ)」を選ぶと、再度カード返金が実行されます**。未選択のままにもせず、「現金」を選んでください
- **過払い返金**: 商品削除・減額後に「返金可能額」が表示されたカード伝票は、下記の手順で「過払い返金」を使います
- **二重決済の検知**: 振込入金後にクレジットカード決済が重なると警告が表示されます。自動では返金されないため、返金処理を行ってください

返金方法は2系統あり、**裏側の挙動が異なります**。

| 返金方法 | 何が起きるか | 対象の支払方法 |
| --- | --- | --- |
| **Shopify(クレカ)** | **実際にクレジットカードへ返金**される | クレジットカード決済 |
| **現金** | EASE に**記録するだけ**。実際の返金は店頭・振込など**オフラインで別途**行う | 現金・銀行振込・その他 |

> **重要:** Shopify 管理画面で直接返金しても、EASE の返金履歴には反映されません。通常は **EASE から返金**し、すでにShopifyで返金済みの場合は **「現金」で記録だけ**を行ってください。

## アクセス方法

1. **伝票検索**（`/slip-search`）で対象の伝票を検索
2. 伝票No. の横の **詳細アイコン**（または「詳細」ボタン）で伝票編集画面を開く
3. 画面下部の **「料金・支払」** セクションへスクロール
4. **「返金」** 行の **「返金を記録」** ボタンをクリック

## 操作手順

### 商品削除・減額後の過払い返金

1. 「料金・支払」セクションに **「返金可能額」** が表示されていることを確認します。
2. **「過払い返金」** を押します。
3. **「返金額（過払い分）」** を確認し、**「返金を実行」** を押します。カードへ返金され、顧客に通知メールが送信されます。

すでにShopifyで返金が完了している場合は、この操作を行わず、下記の「返金を記録」で返金方法を **「現金」** にして記録してください。

### 「返金を記録」で返金する場合

請求書が複数ある場合は、最初に **「返金対象の請求書」** から返金する請求書を選びます。

### 1. 返金額を入力

- 返金したい金額を**円単位**で入力します。
- 「**全額（◯◯）**」ボタンで入金済み金額をワンクリック入力できます。
- 入金済み金額（残高）を**超える額は返金できません**。

### 2. 返金方法を選択

| 選択肢 | 用途 |
| --- | --- |
| **現金** | 店頭返金・銀行振込など、Shopify を通さないオフライン返金の**記録** |
| **Shopify(クレカ)** | クレジットカードへの**実返金** |

> 未選択の場合は、伝票の**支払方法から自動判定**されます（クレカ決済なら Shopify、それ以外なら現金記録）。

> **Shopifyで返金済みの場合は「現金」を選択してください。** 「Shopify(クレカ)」や未選択のままで記録すると、再度カード返金が実行されるおそれがあります。

### 3. 返金理由を入力

- 例:「一部キャンセルによる払い過ぎ返金」
- 経理・監査のため、**理由は具体的に**記入してください。

### 4. 顧客への通知（任意）

- 「**顧客に返金通知メールを送信する**」にチェックを入れると、返金完了時に顧客へメールが送られます。

### 5. 「返金を記録」をクリック

- ボタンを押すと返金が実行され、**返金履歴**に記録されます。

## 入力項目一覧

| 項目 | 種類 | 必須 | 説明 |
| --- | --- | --- | --- |
| 返金対象の請求書 | 選択 | はい（複数ある場合） | 返金する請求書を選択 |
| 返金額 | 数値（円） | はい | 入金済み残高以内 |
| 返金方法 | ラジオ（現金 / Shopify(クレカ)） | 任意 | 未選択時は支払方法から自動判定 |
| 返金理由 | テキスト | 推奨 | 監査・経理のため具体的に |
| 顧客に返金通知メールを送信する | チェックボックス | 任意 | チェック時のみ送信 |

## 返金履歴の見方

「料金・支払」セクションの下に **返金履歴** が一覧表示されます。

![返金履歴の表示](/images/refund-history.png)

| 表示 | 意味 |
| --- | --- |
| （マークなし） | **成功** — 返金が成立 |
| **失敗** | 返金は成立していない（後述の原因を確認） |

ヘッダーのバッジは伝票全体の返金状況を表します:

| バッジ | 意味 |
| --- | --- |
| 未払い | 返金実績なし |
| 一部返金 | 入金額の一部を返金済み |
| 全額返金 | 入金額の全額を返金済み |

## よくある失敗と対処

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| Shopify(クレカ)返金で内部処理のエラーが表示される | 元のクレジットカード決済を特定できない | 最新の画面で再度実行する。解消しない場合はサポートへ連絡する |
| 「返金対象の元決済トランザクションが見つかりません」 | Shopify で支払いが完了していない | 決済済みの注文か確認する。未決済・キャンセル済み注文は Shopify 返金不可 |
| 現金返金したのにクレカに返金されない | 「現金」は**記録のみ**でオフライン返金が前提 | クレカに実返金したい場合は「**Shopify(クレカ)**」を選ぶ |
| Shopify 管理画面で返金したが EASE に反映されない | Shopify 管理画面での返金はEASEの履歴に反映されない | **「返金を記録」で返金方法を「現金」にして記録する**。「Shopify(クレカ)」は再度カード返金を行うため選ばない |

## 金額確定後に返金が必要な場合

貸出伝票は **金額確定後は修正できません**（調整項目の追加・金額の変更不可）。これは業務仕様の定めです。そのため、金額確定後に返金が発生した場合、伝票の金額（入金額）を遡って変更することはできません。

### 事前に対処できる場合（推奨）

返却受付後・**金額確定前**のタイミングであれば、マイナスの調整項目を追加して返金（値引き）を伝票に反映できます。調整金額はプラス・マイナスどちらも入力可能です。

手順は [返却・金額確定処理の「調整項目の追加」](/bookings-return/) を参照してください。

### 金額確定後に返金が必要になった場合

システム上、金額確定後の伝票に調整項目は追加できません。以下の手順で対応してください。

1. **返金処理を行う**: 上記「操作手順」の通り、EASE 管理画面から「返金を記録」を実行してください（クレカ決済は Shopify 経由で実際に返金されます）
2. **伝票備考に返金額を記録する**: 調整項目が追加できないため、返金額は伝票の備考欄（メモ）に手動で記録してください

:::warning
- 返金を実行しても、**伝票の「入金額」は下がりません**（仕様）。伝票一覧では「入金済み」の表示が残ります
- 返金済みかどうかは、**伝票備考の記録**と**返金履歴**（上記）で確認してください
- 可能であれば、**金額確定前にマイナスの調整項目で記録**することをおすすめします（伝票の金額に反映されるため）
:::

## 注意点

- **返金は必ず EASE から**実行してください（Shopify 直返金は同期されません）。
- **Shopify(クレカ)返金は実際にカードへ返金**されます。テスト時も含め、金額・対象を十分確認してから実行してください。
- 入金済み残高を**超える返金はできません**。
- 「失敗」の記録が残っても**実際の返金は発生していません**。原因を解消して再実行してください。

:::dev
クレジットカード返金は Shopify の `refundCreate` を使用します。直接返金が EASE に反映されないのは、返金用 Webhook がないためです。内部の返金方法は `refund_method`、二重決済の警告は `double_payment_suspected`、履歴の内部状態は `COMPLETED` / `FAILED` です。
:::
