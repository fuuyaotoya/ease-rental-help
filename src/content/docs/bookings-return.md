# 返却・金額確定処理

レンタル商品の返却受付から金額確定までを行う画面です。
以下の4つの処理を管理します：

1. **返却予定伝票の返却受付** — 返却日、延長料、破損状況を記録
2. **返却期限超過伝票の対応** — 延滞している伝票の処理
3. **返却済み伝票の金額確定** — 最終的な請求金額を確定
4. **請求済伝票の管理** — Shopify送信済み・入金待ちの伝票

## この画面を開くには

- サイドバーの **「返却・金額確定」** をクリック

---

## 画面上部の統計

![統計エリアとタブ](/images/bookings-return/br-01-stats-tabs.png)

画面上部には4つの統計カードが表示されます。

| 項目 | 説明 |
|------|------|
| 返却予定 | 返却予定日が到来している伝票数 |
| 超過 | 返却期限を過ぎている伝票数 |
| 金額確定待ち | 返却受付済みで金額が未確定の伝票数 |
| 請求済 | Shopify送信済みで入金を待っている伝票数 |

> **💡 「超過中」バッジ（[#2449](https://github.com/iziz-system/ease-rental-frontend/issues/2449)）:** 返却期限を過ぎている伝票は伝票検索・一覧で「**超過中**」の濃い赤バッジで表示されます（キャンセル済みの薄い赤とは別色）。返却受付を済ませると「金額確定待ち」に遷移します。

## 4つのタブ

![タブ一覧](/images/bookings-return/br-01-stats-tabs.png)

画面には4つのタブがあります。

| タブ | 内容 |
|------|------|
| 返却予定一覧 | 返却予定日が到来した伝票 |
| 超過一覧 | 返却期限を過ぎた伝票（出荷済みのもののみ） |
| 金額確定待ち一覧 | 返却済みで金額が未確定の伝票 |

## 操作手順

### ステップ1: 返却受付を行う

1. **「返却予定一覧」** または **「超過一覧」** タブを開きます
2. 返却する伝票の **「↩️ 返却受付」** ボタンをクリックします
3. 返却受付モーダルが開きます

![返却予定一覧](/images/bookings-return/br-02-pending-list.png)

#### 返却受付モーダル

![返却受付モーダル](/images/bookings-return/br-03-return-modal.png)

モーダル上部には伝票情報が表示されます。

| 項目 | 説明 |
|------|------|
| 伝票番号 | リンクをクリックすると伝票詳細に遷移 |
| 顧客名 | 顧客の担当者名 |
| 会社名 | 顧客の会社名 |
| 返却予定日 | 元の返却予定日 |

**返却日の設定:**

- 返却日を入力します（デフォルトは今日）
- 返却予定日より遅い日付を入力すると、**延長料金が自動計算**されます

**商品ごとの設定:**

| 項目 | 説明 |
|------|------|
| チェックボックス | 返却対象に含めるかどうか（全選択/全解除あり） |
| 商品名 | 商品名（「商品ページ↗」リンクでShopify商品ページを開く） |
| SKU | 在庫管理コード |
| 返却予定日 | 元の返却予定日 |
| 実際の返却日 | 実際の返却日 |
| 延長日数 | 延長した日数（自動計算） |
| 延長料金 | 延長料金（自動計算） |
| 破損詳細 | 破損状況の説明（テキスト入力） |
| 🔧 メンテ登録 | メンテナンス期間設定ページへ遷移し、対象商品を自動検索してモーダルを開く（一覧の1ページ目に対象がなくても自動で検索）。見つからない場合は通知が出ます（[#1319](https://github.com/iziz-system/ease-rental-frontend/issues/1319)） |

> **⚠️ 重要:** 延長日数・延長料金は営業日ベースで計算されます。返却日を変更するとリアルタイムで再計算されます。

**料金内訳:**

モーダル下部にリアルタイムの料金内訳が表示されます。

| 項目 | 説明 |
|------|------|
| レンタル料金（税込） | 商品の基本レンタル料金 |
| 延長料金（適用済み） | 金額確定済みの延長料金（確定済み分がある場合のみ表示） |
| 延長料金合計 | 今回の返却受付で発生した延長料金の合計 |
| **今回の追加料金合計** | **延長料金合計（破損料金・調整項目は金額確定モーダルで集計）** |

> **💡 メモ:** 配送料など他の追加料金は次の「金額確定」画面で設定します。

#### 調整項目の追加

![調整項目モーダル](/images/bookings-return/br-04-adjustment-modal.png)

返却受付モーダル内の **「調整項目」** セクションで **「追加」** ボタンをクリックすると、調整項目モーダルが開きます。

:::tip[返却受付以降〜金額確定前のみ追加可能]
調整項目（マイナス含む）は **返却受付以降〜金額確定前** のタイミングでのみ追加できます。返却受付前の伝票では「+ 項目を追加」ボタンが押せず、案内「返却受付前の伝票には調整項目を追加できません。料金を追加する場合はカスタム商品、値引きは伝票値引きをご利用ください」が表示されます（[#1308](https://github.com/iziz-system/ease-rental-frontend/issues/1308)）。金額確定後は伝票が修正ロックされ、調整項目の追加・変更はできません。

**金額確定後** に返金が必要になった場合は、[返金処理の「金額確定後に返金が必要な場合」](/refund/#金額確定後に返金が必要な場合) を参照してください。
:::

**追加できる項目の種類:**

| 種類 | 用途 |
|------|------|
| 価格調整 | 一般的な価格調整 |
| 延長料金 | 延長料金の個別追加 |
| 破損料金 | 破損料金の個別追加 |
| 配送料金 | 配送料金の追加 |
| 駐車場代 | 駐車場代の請求 |
| 高速利用料金 | 高速道路利用料金の請求 |
| その他 | その他の追加料金 |

**入力項目:**

| 項目 | 説明 |
|------|------|
| 種類 | 上記のプルダウンから選択 |
| 金額 | 金額を入力（円） |
| 説明 | 調整理由を入力（顧客向けに転載されるため適切な文言を） |
| 担当者 | 操作担当者を選択 |

> **⚠️ 最大5項目:** 1回の返却受付で追加できる調整項目は最大5件です。

4. 入力が終わったら **「返却受付を確定」** ボタンをクリックします

### ステップ2: 超過伝票の対応

![超過一覧](/images/bookings-return/br-05-overdue-tab.png)

返却期限を過ぎている伝票は **「超過一覧」** タブに表示されます。

**操作は返却予定一覧と同じです：**

1. 対象伝票の **「↩️ 返却受付」** ボタンをクリック
2. 返却日を入力（延長料金が自動計算されます）
3. **「返却受付を確定」** をクリック

> **💡 メモ:** 出荷済みの伝票のみ超過一覧に表示されます。未出荷の伝票は「返却できない」ため表示されません。

---

### ステップ3: 金額を確定する

![金額確定待ち一覧](/images/bookings-return/br-06-confirmation-tab.png)

返却受付済みの伝票は **「金額確定待ち一覧」** タブに移動します。

1. **「金額確定待ち一覧」** タブを開きます
2. 金額を確定する伝票の **「💰 金額確定」** ボタンをクリックします
3. 金額確定モーダルが開きます

![金額確定モーダル](/images/bookings-return/br-07-amount-confirm-modal.png)

**金額確定モーダルで確認・設定する項目:**

- 返却時の延長料金・破損料金の最終確認
- 配送料の追加（未設定の場合）
- 調整項目の追加・修正
- 最終金額の確認

4. 内容を確認し **「金額を確定」** ボタンをクリックします

> **🔔 銀行振込伝票の自動請求書発行（Issue #2260）:**
> 銀行振込（bank_transfer）の伝票で **すべての商品の金額確定が完了した（全件確定）** とき、その伝票の **請求書が自動で発行** され、PDF を添付した **請求書メールが顧客へ自動送信** されます。手動での請求書作成・送信は不要です（クレカ・現金の伝票では発火しません）。自動発行された請求書は [請求一覧](/invoices-list/) で確認できます。※一部返却で未確定の商品が残っている間は発火しません（最後の1件を確定したタイミングで発火）。

> **💡 確定前の延長料は小計に含まれません（[#1317](https://github.com/iziz-system/ease-rental-frontend/issues/1317)）:** 返却時に入力した延長料が金額確定モーダルに表示されていても、確定前は小計に算入されていません。銀行振込等の非クレカ伝票では**確定時に小計へ加算**され、クレジットカード伝票では**確定後に追加請求（DO③）**として別途回収されます。

### ステップ4: Shopify連携（支払方法別）

金額確定後、支払方法に応じて処理が分かれます。

#### クレジットカード（shopify_credit）

金額確定モーダルで **「金額を確定」** をクリックした後、追加請求額 > 0 の場合に同モーダルのフッタに **「📝 追加請求を作成」** ボタンが表示されます（行別の独立ボタンではありません）。

1. **「📝 追加請求を作成」** をクリック
2. Backend が新規 Shopify Draft Order（Draft Order③）を作成
3. Draft Order に延長料金・破損料金・調整項目が line_item として登録される
4. Shopify から顧客のクレジットカードへ自動課金 + 請求書メール送信

> **🗑️ 追加請求を取消:** 追加請求作成後、未決済の Draft Order③ は **「🗑️ 追加請求を取消」** ボタン（Backend #1822 Phase2）で取り消せます。決済済みのものは保護され取消対象外です。

> **背景:** クレカ顧客の本来料金は Draft Order①（注文時）と Draft Order②（配送料確定時）で既に請求済み。延長料金や追加調整は別途 Draft Order③ として作成し、二重請求を防ぎます。

#### 銀行振込（bank_transfer）

**「📤 Shopifyへ送信」** ボタンが表示されます。

1. **「📤 Shopifyへ送信」** をクリック
2. 確認ダイアログで **「OK」** をクリック
3. Backend が Transactional Outbox パターンで非同期処理を開始:
   - Draft Order に送料・追加料金を line item として追記
   - Draft Order を正式な Order に変換
   - `payment_terms` を **翌月末** に設定
   - Shopify から自動で請求メールを送信

**期待される結果:**

- 伝票ステータスが `AMOUNT_CONFIRMED` → `BILLING_PENDING`（請求中）に遷移
- 「Shopify送信ジョブを登録しました」バナーが表示
- Shopifyへの反映は非同期のため数分かかる場合がある

> **送信後の伝票の所在:** 送信完了後、伝票は [請求一覧](/invoices-list/) で入金管理の対象になります。請求一覧で入金確認 → ステータス `COMPLETED` へ遷移。

#### 現金等（その他）

現金等の伝票に手動の完了ボタンはありません（旧「✓ 完了」ボタンは #787/#2084 で撤除済み）。金額確定後、入金記録などの処理を経て自動的に完了ステータスへ遷移します。

## ステータス遷移（金額確定後）

```
金額確定完了（AMOUNT_CONFIRMED）
  ├─ クレカ (shopify_credit):
  │   ├─ 追加請求あり: 📝 追加請求を作成 (Draft Order③) → COMPLETED
  │   └─ 追加請求なし: そのまま → COMPLETED
  ├─ 現金等: 入金記録等で自動遷移 → COMPLETED
  └─ 銀行振込: 📤 Shopifyへ送信 → BILLING_PENDING（請求中）
                                    ↓
                              請求一覧で入金確認
                                    ↓
                              COMPLETED
```

| ステータス | 説明 | 対象 |
|-----------|------|------|
| `AMOUNT_CONFIRMED` | 金額確定済み。Shopify連携待ち | 全支払方法共通 |
| `BILLING_PENDING` | 請求中。Shopify送信済み | 銀行振込のみ |
| `COMPLETED` | 完了。入金確認済みまたは決済完了 | 全支払方法共通 |

> 詳細なステータス定義は [ステータス遷移図](/appendix/status-flow/) を参照。

## 延長料金計算ルール

延長料金は **元の貸出期間を含めた累積日数** で料率が決まります（Issue #2043）。延長日数だけを1日目から数え直すのではありません。

**計算式:**

```
延長料金 = calculateRentalPrice(基本料金, baseline + 延長日数)
         − calculateRentalPrice(基本料金, baseline)
```

- `baseline` = 元の貸出日数（貸出開始日から元の返却予定日までの営業日数）
- 料率 tier は「貸出開始日からの累積日数」で決定

**累積日数ごとの料率（@suite appendix_b 準拠）:**

| 累積日 | 料率 |
|-------|------|
| 1日目 | 基本料金 × 100%（初日基数・延長日には適用されません） |
| 2-6日目 | 基本料金 × 20%/日 |
| 7日目以降 | 基本料金 × 10%/日 |

> **⚠️ 重要:** 延長1日目の料率は baseline（元の貸出日数）により変わります。baseline=1日なら延長1日目は「2日目=20%」ですが、baseline=6日なら延長1日目は「7日目=10%」になります。「延長1日目=必ず20%」は baseline=1日の場合のみ成立します。

**例（基本料金10,000円）:**

| 元の貸出期間(baseline) | 延長日数 | 計算 | 延長料金 |
|----------------------|---------|------|---------|
| 1日 | 1日 | 2日目の20% | +2,000円 |
| 5日 | 2日 | 6日目(20%) + 7日目(10%) | +3,000円 |
| 18日 | 1日 | 19日目の10% | +1,000円 |

## トラブルシューティング

### 一部返却について

- 同一伝票の複数商品を複数回に分けて返却可能
- 伝票No.の横に **「一部返却済」** ラベルで進捗確認可

### よくあるエラー

| エラーメッセージ | 原因 | 対処 |
|----------------|------|------|
| 返却する商品を選択してください | 商品が未選択 | チェックボックスで返却対象を選択 |
| 返却日を入力してください | 返却日未入力 | 返却日フィールドに日付を入力 |
| 以下の商品の返却処理に失敗しました | API通信エラー | 再度実行、または個別に処理 |

## 検証チェックリスト

- [ ] 返却受付日が正しく設定されている
- [ ] 返却数量が貸出数量以下
- [ ] 破損がある場合、破損詳細と料金が入力されている
- [ ] 調整項目の説明欄が顧客向け文言として適切（Shopify line_item に転載される）
- [ ] 料金内訳の合計が正しい
- [ ] クレカ顧客で追加請求がある場合、「📝 追加請求を作成」を実行済み
- [ ] 銀行振込顧客の場合、「📤 Shopifyへ送信」を実行済み
