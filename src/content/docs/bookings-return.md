> **パス:** `/bookings-return`
> **メニュー:** 返却・金額確定

## 概要

レンタル商品の返却受付から金額確定までを行います。この画面では以下の3つの処理を管理します:

- 返却予定伝票の返却受付
- 返却期限超過伝票の対応
- 返却済み伝票の金額確定

## アクセス方法

- サイドバーから: **返却・金額確定** をクリック
- URL直接: `/bookings-return`

## 操作手順

### 手順1: 返却受付（返却予定/超過タブ）

1. 「返却予定一覧」または「超過一覧」タブをクリック
2. 返却する伝票の「返却受付」ボタンをクリック
3. **返却受付処理モーダル** が開きます
![返却受付モーダル](/images/uat/return-modal.png)

4. 以下の項目を入力:
   - **返却日設定（期間延長）**: 新しい返却日を入力し「設定」ボタンで期間延長を確定（営業日基準で延長料金が自動再計算）
   - **商品ごとの設定**:
     - 選択: 返却対象に含めるチェック
     - 返却数: 実際に返却された数量
     - 延長日数: 延長した日数（自動計算、概算）
     - 延長料金: 延長料金（自動計算、概算）
     - 状態: 良好/軽微な破損/重大な破損/紛失
     - 破損詳細: 破損状況の説明
     - 破損料金: 破損に伴う追加料金
   - **調整項目**: 「追加」ボタンで追加料金（駐車場代・高速利用料金等）を登録（後述の調整項目モーダル参照）
   - **返却メモ**: 返却時の状況や注意事項
5. 「返却受付を確定」ボタンをクリック

> **注:** 表に表示される延長日数・延長料金は **暦日ベースの概算** です。期間延長を「設定」ボタンで確定すると、Backend が **営業日基準の段階レート** で再計算した値で上書きされます（Issue #980）。

**期待される結果:**

- 選択した商品が「返却済み」ステータスに変更
- 延長料金・破損料金が記録される
- 伝票が「金額確定待ち」に移動

### 手順2: 金額確定（金額確定待ちタブ）

![金額確定モーダル](/images/uat/amount-confirm-modal.png)

1. 「金額確定待ち一覧」タブをクリック
2. 金額を確定する伝票の「金額確定」ボタンをクリック
3. **金額確定モーダル** が開きます
4. 以下の項目を確認・入力:
   - **返却済み商品**: 確定対象の商品を選択
   - **延長料金**: 返却時に入力済み（参照のみ）
   - **破損料金**: 返却時に入力済み（参照のみ）
   - **配送料**: 配送料の調整（入力可）
   - **調整項目**: 「編集」ボタンで追加料金・割引を登録（後述の **手順2-C** 参照）
   - **メモ**: 金額確定時のメモ
5. 料金内訳を確認
6. 「金額を確定」ボタンをクリック

> **変更履歴 (Issue #993):** 旧UIにあった独立した「駐車場代」入力欄は廃止され、**調整項目**に統合されました。駐車場代を入力する場合は「調整項目」の追加から **種類=駐車場代** を選択してください。

### 手順2-C: 調整項目モーダル

![調整項目モーダル](/images/uat/adjustment-modal.png)

「調整項目」セクションの「追加」または「編集」ボタンで調整項目モーダルが開きます。

**入力項目:**

| 項目 | 内容 |
|------|------|
| 種類 | 価格調整 / 延長料金 / 破損料金 / 配送料金 / **駐車場代** / **高速利用料金** / その他 |
| 金額 (円) | 正の値で追加請求、負の値で割引 |
| 説明 | 顧客向けの説明文（Shopify line_item の note にも転載される） |
| 担当者 | 調整を登録したスタッフを選択 |

**Issue #1742 (Backend) 仕様:** クレカ顧客の場合、調整項目は Shopify Draft Order の line_item として転送され、説明欄の内容が顧客側で確認できます。

**期待される結果:**

- 金額が確定し、Draft Orderに追加請求として反映
- 「請求書作成へ」リンクが表示される

### 手順3: Shopify連携（支払方法別）

金額確定後、支払方法に応じて処理が分かれます。

#### 手順3-A: 📝 追加請求を作成（クレジットカード）

`payment_method` が `shopify_credit` の伝票で、延長料金・破損料金・調整項目等の **追加請求額が0円より大きい** 場合に表示されます。

**表示条件:**

- 支払方法が `shopify_credit`
- 金額確定済み（同じモーダル内で「金額を確定」を押した直後）
- 追加請求額 > 0（延長料金・破損料金・調整項目の合計）

**操作手順:**

1. 金額確定モーダル内で「金額を確定」を押す
2. 「📝 追加請求を作成」ボタンが活性化
3. ボタンをクリック → Backend が新規 Shopify Draft Order（**Draft Order③**）を作成
4. Draft Order には延長料金・破損料金・調整項目（駐車場代・高速利用料金等）が line_item として登録される
5. Shopify から顧客のクレジットカードへ自動課金 + 請求書メール送信

**期待される結果:**

- ボタンの表示が「送信済み」に変化
- Shopify Admin で新規 Draft Order が確認可能
- 調整項目の説明欄が line_item の note として転送される（Issue #1742）

> **背景:** クレカ顧客の本来料金は **Draft Order①**（注文時）と **Draft Order②**（配送料確定時）で既に請求済み。延長料金や追加調整は別途 **Draft Order③** として作成し、二重請求を防ぐ設計です。

#### 手順3-B: Draft Order完了（旧フロー・現金払い等）

`payment_method` が `bank_transfer` / `shopify_credit` 以外で、かつ `shopifyDraftOrderGid` が存在する伝票:

1. 「Draft Order完了」ボタンをクリック
2. 確認ダイアログで「OK」をクリック
3. Draft Orderが正式なOrderに変換されます

**期待される結果:**

- Shopify上でDraft Orderが完了
- Order番号が表示される

#### 手順3-C: 📤 Shopifyへ送信（銀行振込）

`payment_method` が `bank_transfer` の伝票にのみ「📤 Shopifyへ送信」ボタンが表示されます。

**表示条件:**

- 対象伝票の支払方法が `bank_transfer`（銀行振込）
- 金額確定済み（`returnStatus = amount_confirmed`）

**操作手順:**

1. 「📤 Shopifyへ送信」ボタンをクリック
   - ボタンは **金額確定待ちタブ** の対象伝票行、または金額確定モーダル内に表示
   - 金額確定前はボタンが無効化（「金額確定後に送信できます」ツールチップ）
2. 確認ダイアログ「送料・追加料金をShopifyへ送信しますか？」で「OK」をクリック
3. バックエンドが Transactional Outbox パターンで非同期処理を開始:
   - Draft Order に送料・追加料金を line item として追記
   - Draft Order を正式な Order に変換
   - `payment_terms` を **翌月末** に設定
   - Shopify から自動で請求メールを送信

**期待される結果:**

- 伝票ステータスが `AMOUNT_CONFIRMED` → `BILLING_PENDING`（請求中）に遷移
- 「Shopify送信ジョブを登録しました」バナーが表示される
- Shopifyへの反映は非同期のため数分かかる場合がある

**送信後の伝票の所在:**

- 送信完了後、伝票は [`/invoices-list`](11_invoices-list.md)（請求一覧）で入金管理の対象になる
- 請求一覧で入金確認 → ステータス `COMPLETED` へ遷移

> **@Suite との違い:** @Suiteでは自社で請求書を発行していましたが、新システムでは **Shopifyが請求書の発行・メール送信を担当** します。管理画面からは送信のトリガーと入金確認のみ行います。

## ステータス遷移（金額確定後）

```
金額確定完了（AMOUNT_CONFIRMED）
  ├─ クレカ (shopify_credit):
  │   ├─ 追加請求あり: 📝 追加請求を作成 (Draft Order③) → COMPLETED
  │   └─ 追加請求なし: そのまま → COMPLETED
  ├─ 現金等: Draft Order完了 → COMPLETED
  └─ 銀行振込: 📤 Shopifyへ送信 → BILLING_PENDING（請求中）
                                    ↓
                              請求一覧で入金確認 → COMPLETED
```

| ステータス         | 説明                              | 対象           |
| ------------------ | --------------------------------- | -------------- |
| `AMOUNT_CONFIRMED` | 金額確定済み。Shopify連携待ち     | 全支払方法共通 |
| `BILLING_PENDING`  | 請求中。Shopify送信済み・入金待ち | 銀行振込のみ   |
| `COMPLETED`        | 完了。入金確認済みまたは決済完了  | 全支払方法共通 |

> 詳細なステータス定義は `docs/manual/appendix_a_status-flow.md` を参照。

## 延長料金計算ルール

延長料金は以下のルールで自動計算されます:

| 延長日数  | 計算式            | 例（基本料金1,000円） |
| --------- | ----------------- | --------------------- |
| 1日目     | 基本料金 × 20%    | +200円                |
| 2日目     | 基本料金 × 20%    | +200円                |
| 3日目     | 基本料金 × 20%    | +200円                |
| 4日目     | 基本料金 × 20%    | +200円                |
| 5日目     | 基本料金 × 20%    | +200円                |
| 6日目     | 基本料金 × 20%    | +200円                |
| 7日目以降 | 基本料金 × 10%/日 | +100円/日             |

**例:** 基本料金1,000円で8日間延長の場合

- 1-6日目: 1,000 × 20% × 6 = 1,200円
- 7-8日目: 1,000 × 10% × 2 = 200円
- **合計: 1,400円**

## トラブルシューティング

### 一部返却について

- 同一伝票の複数商品を複数回に分けて返却可能
- 「一部返却済」「一部確定済」ラベルで進捗確認可

### よくあるエラー

| エラーメッセージ                   | 原因             | 対処方法                         |
| ---------------------------------- | ---------------- | -------------------------------- |
| 返却する商品を選択してください     | 商品が未選択     | チェックボックスで返却対象を選択 |
| 返却日を入力してください           | 返却受付日未入力 | 返却受付日を設定                 |
| 以下の商品の返却処理に失敗しました | API通信エラー    | 再度実行、または個別に処理       |

## 検証チェックリスト

- [ ] 返却受付日が正しく設定されている
- [ ] 返却数量が貸出数量以下
- [ ] 商品の状態が正しく選択されている
- [ ] 破損がある場合、破損詳細と料金が入力されている
- [ ] 期間延長を行った場合、「設定」ボタンを押して営業日基準で再計算済み
- [ ] 駐車場代・高速利用料金は **調整項目** から登録（旧UIの独立欄は廃止）
- [ ] 調整項目の説明欄が顧客向け文言として適切（Shopify line_item に転載される）
- [ ] クレカ顧客で追加請求がある場合、「📝 追加請求を作成」ボタンを実行
- [ ] 料金内訳の合計が正しい
