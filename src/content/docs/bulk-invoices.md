## 概要

**請求先単位**で対象月の請求書を作成し、確認してから手動で送信します。月次の自動生成は毎月28日23:00（日本時間）に実行されます。自動送信は行いません。この画面では、プレビュー → 生成 → 送信を手動で実行できます。

対象は、顧客マスタの有効な請求先で「まとめ請求対象」が設定されている、未払い・金額確定済みの銀行振込伝票です。取消済み、削除済み、社内確保、既にまとめ請求書に含まれる伝票は対象外です。対象月末までに貸出を開始した伝票を抽出するため、過去の未払い確定分も含まれます。「銀行振込可」タグだけでは月次対象になりません。

**顧客アカウントのPDFは手動送信後に表示されます。** 月次の作成前やドラフト段階で表示されないことは正常です。表示場所と確認方法は[会社まとめ請求の表示条件](/consolidated-invoices/#顧客アカウントで表示される条件)をご覧ください。

> **当画面と会社まとめ請求の違い（重要）:**
>
> | 画面 | 集約単位 | 同じ会社の別部署 |
> | --- | --- | --- |
> | **当画面（bulk-invoices）** | 請求先（会社名＋部署）単位 | 別の請求書になる |
> | [会社まとめ請求](/consolidated-invoices) | 請求先（会社名＋部署）キーで複数の顧客レコードを1枚に集約 | 別の請求書になる |
>
> 会社まとめ請求は「同じ会社名＋同じ部署」に正規化される複数の顧客レコード／請求先を1枚にまとめます。**部署が異なれば別の請求書になる**点は当画面と同じです（部署を横断して1枚にまとめる集約は行われません）。

## 画面構成

### フォームセクション

| 項目                     | 種類             | 説明                                                                                              | 必須 |
| ------------------------ | ---------------- | ------------------------------------------------------------------------------------------------- | ---- |
| 対象月                   | セレクト         | 請求対象月（YYYY-MM形式）。過去12ヶ月〜未来3ヶ月から選択。当月は「(当月)」ラベル付き               | Yes  |

> ※「企業グループ」などの絞り込み項目は**存在しません**。対象は請求先（部署）単位で自動抽出されます。

### アクションボタン

| ボタン     | 色       | 説明                                                       |
| ---------- | -------- | ---------------------------------------------------------- |
| プレビュー | 青       | 処理内容のプレビュー（dry_run=true・請求書は作成されない） |
| 請求書生成 | 緑       | 請求書の実際の生成                                         |
| 請求書送信 | オレンジ | 生成済み請求書のメール送信（送信可能な請求書がある場合のみ有効） |
| リセット   | 灰色     | フォームと結果をリセット                                   |

### サマリーセクション

生成完了後に「処理結果サマリー」が表示されます:

- **合計**件数
- **成功**件数
- **スキップ**件数
- **失敗**件数
- **合計金額**

### 結果セクション

**生成結果**は以下の列のテーブルで表示されます（請求先＝会社名＋部署 ごとに1行）:

- 会社名
- 部署
- 件数（その請求先に含まれる伝票数）
- 金額
- 状態（成功 / スキップ / 失敗）
- 請求書番号
- 備考（エラー・スキップ理由）

**送信結果**は送信実行後に以下の列で表示されます:

- 会社名
- 請求書番号
- 状態（成功 / 失敗）
- 備考

## 3フェーズ処理フロー

```
┌──────────────────────────────────────────────────────────────┐
│  Phase 1: プレビュー                                          │
│  - dry_run=true で安全に処理内容を確認                         │
│  - 請求書は作成されない                                        │
│  - 対象件数・金額の確認                                        │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Phase 2: 請求書生成                                          │
│  - dry_run=false で実際の請求書を作成                          │
│  - ドラフト状態で保存される                                     │
│  - まだメールは送信されない                                     │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Phase 3: 請求書送信                                          │
│  - 生成された請求書をメール送信                                 │
│  - ステータスが「送信済み」に変更                               │
│  - 処理完了                                                   │
└──────────────────────────────────────────────────────────────┘
```

## 操作手順

### 手順1: 条件設定

1. **対象月**を選択
   - 過去12ヶ月〜未来3ヶ月から選択可能
   - 当月は「(当月)」ラベル付き
2. 顧客マスタの請求先が有効で「まとめ請求対象」が設定されていることを確認

### 手順2: プレビュー実行

1. 「プレビュー」ボタンをクリック
2. 処理中はボタンにローディング表示
3. プレビュー結果が表示されます

**期待される結果:**

- 対象となる請求書の一覧が表示
- 各請求先（部署）ごとの件数・金額
- **請求書はまだ作成されていません**

### 手順3: 請求書生成

1. プレビュー内容を確認
2. 「請求書生成」ボタンをクリック
3. 確認ダイアログで「生成する」をクリック
4. 処理完了まで待機

**期待される結果:**

- 請求書がドラフト状態で作成される
- 生成結果がテーブルに表示
- 「請求書送信」ボタンが有効化

### 手順4: 請求書送信

1. 生成された請求書の内容を確認
2. 「請求書送信」ボタンをクリック
3. 確認ダイアログで「送信する」をクリック
4. メール送信処理が実行されます

**期待される結果:**

- 各請求先にメールが送信される
- 請求書ステータスが「送信済み」に変更
- 送信結果が表示される

### 手順5: リセット（次の処理へ）

1. 「リセット」ボタンをクリック
2. フォームと結果がクリアされます
3. 次の月次処理に備える

## 使用例

### 月次一括請求の典型的なワークフロー

```
月初（締め日翌日以降）:
1. 前月分の返却・金額確定がすべて完了していることを確認
2. 「月次請求書一括処理」画面を開く（URL直接入力）
3. 対象月 = 前月 を選択
4. 請求先の月次設定と銀行振込の支払方法を確認
5. 「プレビュー」で対象を確認
6. 内容を確認後、「請求書生成」
7. 生成された請求書を確認
8. 問題なければ「請求書送信」
9. 送信完了を確認
```

> この処理は、毎月28日23:00（日本時間）に自動生成する月次請求バッチと同じ対象（請求先＝部署単位）を手動で実行するものです。

## ヘルプ情報

画面下部に使い方のガイドが表示されます:

1. 対象月を選択してください（請求先＝部署単位で1件ずつ請求書を作成します）
2. 有効な請求先の「まとめ請求対象」と、金額確定済みの銀行振込伝票を確認してください
3. まず「プレビュー」で処理内容を確認してください
4. 内容を確認後、「請求書生成」で請求書を作成します
5. 生成された請求書はドラフト状態で保存されます
6. 「請求書送信」でメール送信を行います

> ※ 本処理は月次の自動生成と同じ対象（請求先単位）を手動実行するものです。なお会社まとめ請求のグルーピングも請求先（会社名＋部署）キーのため、部署が異なる伝票は別々の請求書になります。

## 通知・エラー

### 成功時

| メッセージ                | タイミング       |
| ------------------------- | ---------------- |
| プレビューが完了しました  | プレビュー完了時 |
| N件の請求書を生成しました | 生成完了時       |
| N件の請求書を送信しました | 送信完了時       |

### エラー表示

エラーが発生した場合、画面上部に赤いアラートが表示されます:

```
エラーが発生しました
{エラー詳細}
```

**主なエラー:**

| エラー                   | 原因             | 対処方法               |
| ------------------------ | ---------------- | ---------------------- |
| 未入金データがありません | 対象データなし   | 対象月を確認           |
| API通信エラー            | ネットワーク問題 | 再度実行               |
| - 認証エラー             | トークン期限切れ | 再ログイン             |
| - バリデーションエラー   | データ不整合     | 個別に対応             |

> ※「スキップ」はエラーではなく、その請求先が請求書発行対象外（例: 0円・未確定・[社内確保](/internal-hold/)）のため対象から外れた状態です。結果テーブルの「備考」列にスキップ理由が表示されます。

### プレビュー前

- [ ] 対象月が正しい
- [ ] 請求先の月次設定と銀行振込の支払方法が正しい

### 生成前

- [ ] プレビュー結果の件数が想定通り

### 送信前

- [ ] 生成された請求書の内容を確認
- [ ] 請求先メールアドレスが正しい
- [ ] 送信しても問題ない状態か確認

## 注意事項

### 安全性の仕組み

- **プレビューは必須**: 生成前に必ずプレビューで確認
- **dry_run=true**: プレビューは実際のデータを作成しない
- **ドラフト保存**: 生成直後はドラフト状態（送信されない）
- **確認ダイアログ**: 生成・送信前に確認を要求

### 処理タイミング

- 当画面は通常、月次の**自動生成と同じ対象を手動確認・生成・送信する**ための画面です
- 前月分の返却・金額確定が完了してから実行
- 送信は業務時間内に行う（問い合わせ対応のため）

## API仕様（参考）

### エンドポイント

| 処理       | エンドポイント           | dry_run |
| ---------- | ------------------------ | ------- |
| プレビュー | GET /bulk-invoices/preview | true    |
| 生成       | POST /bulk-invoices/generate | false   |
| 送信       | POST /bulk-invoices/send | -       |

### パラメータ

```typescript
{
  invoice_month: string;          // YYYY-MM形式
  filter_bank_transfer?: boolean; // 互換パラメータ。対象は常に銀行振込・月次設定により決定
  dry_run: boolean;               // true: プレビュー, false: 生成
}
```
