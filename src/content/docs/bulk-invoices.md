## 概要

**請求先（部署）単位**で当月分の請求書を一括生成・送信します。締め日翌日早朝に自動実行される月次請求と同じ対象・処理を手動で実行する画面です。3フェーズの処理フロー（プレビュー → 生成 → 送信）に従って安全に処理を行います。

> **当画面と会社まとめ請求の違い（重要）:**
>
> | 画面 | 集約単位 | 同じ会社の別部署 |
> | --- | --- | --- |
> | **当画面（bulk-invoices）** | 請求先（会社名＋部署）単位 | 別の請求書になる |
> | [会社まとめ請求](/consolidated-invoices) | 同じ会社全体を1枚に集約 | 1枚の請求書にまとまる |
>
> 同じ会社の複数部署を1枚の請求書にまとめたい場合は、[会社まとめ請求](/consolidated-invoices)をご利用ください。

## アクセス方法

- **URL直接**: `/bulk-invoices`（サイドバーからは非表示です）
- 新規の月次処理には [会社まとめ請求](/consolidated-invoices) をご利用ください

## 画面構成

### フォームセクション

| 項目                     | 種類             | 説明                                                                                              | 必須 |
| ------------------------ | ---------------- | ------------------------------------------------------------------------------------------------- | ---- |
| 対象月                   | セレクト         | 請求対象月（YYYY-MM形式）。過去12ヶ月〜未来3ヶ月から選択。当月は「(当月)」ラベル付き               | Yes  |
| 銀行振込可タグでフィルタ | チェックボックス | チェックすると、銀行振込での支払いが可能な請求先（bank_transfer タグ保有）のみを対象にします     | -    |

> ※「企業グループ」などの絞り込み項目は**存在しません**。対象は請求先（部署）単位で自動抽出されます。

### アクションボタン

| ボタン     | 色       | 説明                                                       |
| ---------- | -------- | ---------------------------------------------------------- |
| プレビュー | 青       | 処理内容のプレビュー（dry_run=true・請求書は作成されない） |
| 請求書生成 | 緑       | 請求書の実際の生成                                         |
| 請求書送信 | オレンジ | 生成済み請求書のメール送信（送信可能な請求書がある場合のみ有効） |
| リセット   | 灰色     | フォームと結果をリセット                                   |

### サマリーセクション

生成完了後に「処理結果サマリー」が表示されます:

- **合計**件数
- **成功**件数
- **スキップ**件数
- **失敗**件数
- **合計金額**

### 結果セクション

**生成結果**は以下の列のテーブルで表示されます（請求先＝会社名＋部署 ごとに1行）:

- 会社名
- 部署
- 件数（その請求先に含まれる伝票数）
- 金額
- 状態（成功 / スキップ / 失敗）
- 請求書番号
- 備考（エラー・スキップ理由）

**送信結果**は送信実行後に以下の列で表示されます:

- 会社名
- 請求書番号
- 状態（成功 / 失敗）
- 備考

## 3フェーズ処理フロー

```
┌──────────────────────────────────────────────────────────────┐
│  Phase 1: プレビュー                                          │
│  - dry_run=true で安全に処理内容を確認                         │
│  - 請求書は作成されない                                        │
│  - 対象件数・金額の確認                                        │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Phase 2: 請求書生成                                          │
│  - dry_run=false で実際の請求書を作成                          │
│  - ドラフト状態で保存される                                     │
│  - まだメールは送信されない                                     │
└──────────────────────────────────────────────────────────────┘
                          ↓
┌──────────────────────────────────────────────────────────────┐
│  Phase 3: 請求書送信                                          │
│  - 生成された請求書をメール送信                                 │
│  - ステータスが「送信済み」に変更                               │
│  - 処理完了                                                   │
└──────────────────────────────────────────────────────────────┘
```

## 操作手順

### 手順1: 条件設定

1. **対象月**を選択
   - 過去12ヶ月〜未来3ヶ月から選択可能
   - 当月は「(当月)」ラベル付き
2. **銀行振込可タグでフィルタ**にチェック（必要な場合）
   - チェックすると、銀行振込での支払いが可能な請求先のみが対象

### 手順2: プレビュー実行

1. 「プレビュー」ボタンをクリック
2. 処理中はボタンにローディング表示
3. プレビュー結果が表示されます

**期待される結果:**

- 対象となる請求書の一覧が表示
- 各請求先（部署）ごとの件数・金額
- **請求書はまだ作成されていません**

### 手順3: 請求書生成

1. プレビュー内容を確認
2. 「請求書生成」ボタンをクリック
3. 確認ダイアログで「生成する」をクリック
4. 処理完了まで待機

**期待される結果:**

- 請求書がドラフト状態で作成される
- 生成結果がテーブルに表示
- 「請求書送信」ボタンが有効化

### 手順4: 請求書送信

1. 生成された請求書の内容を確認
2. 「請求書送信」ボタンをクリック
3. 確認ダイアログで「送信する」をクリック
4. メール送信処理が実行されます

**期待される結果:**

- 各請求先にメールが送信される
- 請求書ステータスが「送信済み」に変更
- 送信結果が表示される

### 手順5: リセット（次の処理へ）

1. 「リセット」ボタンをクリック
2. フォームと結果がクリアされます
3. 次の月次処理に備える

## 使用例

### 月次一括請求の典型的なワークフロー

```
月初（締め日翌日以降）:
1. 前月分の返却・金額確定がすべて完了していることを確認
2. 「月次請求書一括処理」画面を開く（URL直接入力）
3. 対象月 = 前月 を選択
4. 必要に応じて「銀行振込可タグでフィルタ」にチェック
5. 「プレビュー」で対象を確認
6. 内容を確認後、「請求書生成」
7. 生成された請求書を確認
8. 問題なければ「請求書送信」
9. 送信完了を確認
```

> この処理は、締め日翌日早朝に自動実行される月次請求バッチと同じ対象（請求先＝部署単位）を手動で実行するものです。

## ヘルプ情報

画面下部に使い方のガイドが表示されます:

1. 対象月を選択してください（請求先＝部署単位で1件ずつ請求書を作成します）
2. 「銀行振込可タグでフィルタ」を有効にすると、銀行振込での支払いが可能な請求先のみを対象にします
3. まず「プレビュー」で処理内容を確認してください
4. 内容を確認後、「請求書生成」で請求書を作成します
5. 生成された請求書はドラフト状態で保存されます
6. 「請求書送信」でメール送信を行います

> ※ 本処理は締め日翌日早朝の自動請求と同じ対象（請求先単位）を手動実行するものです。同じ会社の複数部署を1枚の請求書にまとめたい場合は「会社まとめ請求」をご利用ください。

## 通知・エラー

### 成功時

| メッセージ                | タイミング       |
| ------------------------- | ---------------- |
| プレビューが完了しました  | プレビュー完了時 |
| N件の請求書を生成しました | 生成完了時       |
| N件の請求書を送信しました | 送信完了時       |

### エラー表示

エラーが発生した場合、画面上部に赤いアラートが表示されます:

```
エラーが発生しました
{エラー詳細}
```

**主なエラー:**

| エラー                   | 原因             | 対処方法               |
| ------------------------ | ---------------- | ---------------------- |
| 未入金データがありません | 対象データなし   | 対象月を確認           |
| API通信エラー            | ネットワーク問題 | 再度実行               |
| - 認証エラー             | トークン期限切れ | 再ログイン             |
| - バリデーションエラー   | データ不整合     | 個別に対応             |

> ※「スキップ」はエラーではなく、その請求先が請求書発行対象外（例: 0円・未確定）のため対象から外れた状態です。結果テーブルの「備考」列にスキップ理由が表示されます。

## 検証チェックリスト

### プレビュー前

- [ ] 対象月が正しい
- [ ] フィルタ条件（銀行振込可タグ）が意図通り

### 生成前

- [ ] プレビュー結果の件数が想定通り
- [ ] 請求金額が妥当
- [ ] 前月分の返却・金額確定が完了している

### 送信前

- [ ] 生成された請求書の内容を確認
- [ ] 請求先メールアドレスが正しい
- [ ] 送信しても問題ない状態か確認

## 注意事項

### 安全性の仕組み

- **プレビューは必須**: 生成前に必ずプレビューで確認
- **dry_run=true**: プレビューは実際のデータを作成しない
- **ドラフト保存**: 生成直後はドラフト状態（送信されない）
- **確認ダイアログ**: 生成・送信前に確認を要求

### 処理タイミング

- 当画面は通常、締め日翌日早朝の**自動バッチと同じ処理の手動実行**用です
- 前月分の返却・金額確定が完了してから実行
- 送信は業務時間内に行う（問い合わせ対応のため）

## API仕様（参考）

### エンドポイント

| 処理       | エンドポイント           | dry_run |
| ---------- | ------------------------ | ------- |
| プレビュー | POST /bulk-invoices      | true    |
| 生成       | POST /bulk-invoices      | false   |
| 送信       | POST /bulk-invoices/send | -       |

### パラメータ

```typescript
{
  invoice_month: string;          // YYYY-MM形式
  filter_bank_transfer?: boolean; // 銀行振込可タグでフィルタ
  dry_run: boolean;               // true: プレビュー, false: 生成
}
```
