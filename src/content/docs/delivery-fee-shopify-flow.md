## 概要

配送料が0円でShopifyに注文が作成される場合、配送料確定後にShopifyへ別途請求を行う必要があります。本手順書では、バックエンド管理画面から配送料を確定し、Shopify経由で顧客へ請求書メールを送信するまでの流れを説明します。

## 前提条件

- 対象伝票はすでに出荷済みであること
- 配送料金が確定していること
- 顧客のメールアドレスが登録されていること
- 顧客の支払方法がクレジットカードであること

## 処理フロー

### Step 1: メニューを開く

バックエンド管理画面のサイドバーから「**配送料確定（クレカ）**」メニューを開きます。

### Step 2: 伝票一覧で対象を選択

![配送料確定一覧](/images/uat/shipping-fee-list.png)

一覧は以下の **6列構成**（コンパクト表示）になっています:

| 列 | 内容 |
|----|------|
| 伝票No. | クリックで booking-compact 詳細ページへ遷移 |
| 顧客No. | Shopify 顧客コード |
| 顧客名 | 顧客名 |
| 会社名 | 会社名（個人の場合は「-」または「個人」） |
| 配送数 | 当該伝票の配送レコード数（往路+復路） |
| 操作 | 「配送料確認」ボタン |

> **Issue #994 改善:** 旧版で表示されていた **部署名列は廃止** されました。横スクロールを抑え、ボタンが切れないコンパクトな表示に変更されています。

### Step 3: 配送料確認画面で金額を入力

![配送料確定詳細画面](/images/uat/shipping-fee-detail.png)

「配送料確認」ボタン押下後、専用ページ (`/bookings-shipping-fee/[id]`) に遷移します。

**画面構成:**

- **伝票情報**: 伝票番号・顧客名・会社名・レンタル期間・配送先住所
- **配送明細・料金確定**: 往路（搬入）と復路（搬出）それぞれに配送料入力欄
- **追加料金**: 「+追加」ボタンで任意の追加料金を登録可能
- **小計（税抜）/ 消費税 / 合計（税込）**: 自動計算

配送料金を入力後、「**Shopifyへ送信**」ボタンを押下します。

### Step 4: 送信完了を確認

画面に「**Shopifyに送信しました**」と表示されれば、Shopify側への送信は完了です。

### Step 5: 請求書メールの送信を確認

Shopifyから顧客のメールアドレス宛に請求書メールが自動送信されます。顧客はメール内のリンクから決済可能です。

## 確認ポイント

| 項目         | 説明                                    |
| ------------ | --------------------------------------- |
| 伝票番号     | バックエンド側で作成される              |
| 請求書メール | Shopifyから自動送信。伝票番号が含まれる |
| 決済リンク   | 顧客はメール内リンクから決済可能        |
| 対象支払方法 | クレジットカード（銀行振込は別フロー）  |

## よくある質問

### Q: 銀行振込の顧客の場合はどうすればよいですか？

銀行振込の顧客は本フローの対象外です。銀行振込注文の下書き仕様に従って別途処理してください。

### Q: 配送料を修正したい場合はどうすればよいですか？

Shopifyへ送信前であれば、再度配送料を入力し直すことができます。送信後の修正は、Shopify管理画面からDraft Orderを編集してください。

### Q: 顧客がメールを受け取っていない場合は？

1. 顧客のメールアドレスが正しく登録されているか確認
2. 迷惑メールフォルダを確認するよう顧客へ連絡
3. Shopify管理画面から請求書を再送信

## 追加請求（Draft Order③）との違い

本フローは **Draft Order②（配送料確定請求）** です。返却後に発生する延長料金・破損料金・調整項目（駐車場代等）は **Draft Order③** として **[返却・金額確定](/bookings-return/)** ページの「📝 追加請求を作成」ボタンで別途請求します。

| Draft Order | タイミング | 内容 | 操作画面 |
|------------|-----------|------|---------|
| ① | 注文時 | 商品レンタル料金 | （Shopify ストア側） |
| ② | 配送料確定時 | 配送料金 | このページ（配送料確定（クレカ）） |
| ③ | 金額確定時 | 延長料金・破損料金・調整項目 | [返却・金額確定](/bookings-return/) |
| ⑤ | 配送キャンセル時（※DO②未作成の場合のみ） | 配送キャンセル料 | [伝票作成・編集](/booking-compact/)（下記「配送キャンセル料（DO⑤）」） |

## 配送キャンセル料のクレカ後課金（Draft Order⑤）

クレジットカード決済の伝票で **配送がキャンセルされた** 場合、そのキャンセル料を別途回収するための Draft Order⑤ を発行します。

### 対象シナリオ（すべて満たす必要があります）

- クレジットカード決済（Shopify）の伝票である
- 配送がキャンセルされ、**キャンセル料が0円超で入力されている**
- **配送料 Draft Order② をまだ送信していない**（請求チャネルの②が「--」）
- 伝票が「完了」「キャンセル」状態ではない
- 顧客のメールアドレスが登録されている

> **⚠️ 配送料DO②を「すでに送信済み」の場合は対象外**
> 本機能は **DO②未作成（＝配送料をまだShopifyに送っていない）** の伝票のみ対象です。DO②送信済み（請求チャネル②が「送信済」）の場合はボタンが表示されません。
> - **DO②未入金で残っている場合**: Shopify管理画面で該当Draft Orderを削除しても、**本システム側のステータスは自動で「--」に戻りません**（Shopifyの削除と本システムが連動していないため・既知の運用課題）。システム管理者による個別対応が必要です（下記FAQ参照）。
> - **DO②入金済みの場合**: 削除できません。キャンセル料は別途（手動でDraft Order作成等）で回収してください。

### 手順

1. [伝票作成・編集](/booking-compact/) ページで対象伝票を開く
2. 「請求チャネル」欄の近くに「**キャンセル料を請求する（DO⑤）**」ボタンが表示される（上記条件を満たす場合のみ）
3. ボタンクリック → 確認ダイアログで **対象配送数** と **請求額**（各配送のキャンセル料合計・税込・バックエンド算出）を確認
4. 必要に応じて **メモ**（500文字以内・Shopify Draft Orderのメモに反映）を入力
5. 「**請求を作成**」をクリック

### 作成経路（非同期ジョブ）

「請求を作成」を押すと、バックエンドが **非同期ジョブ** を登録し、即座に「作成しました（決済待ち）」と表示されます。実際のShopify処理はバックグラウンドで行われます。

```
ボタン押下
  ↓ POST /bookings/:id/create-cancellation-fee-draft-order (delivery_ids + memo)
バックエンド: バリデーション → ジョブ登録 → 即時レスポンス(job_id, 決済待ち)
  ↓ (非同期ワーカー起動)
ワーカー: 各配送のcancellation_feeから請求額算出
  → Shopifyに Draft Order⑤ を作成
  → 伝票にGIDを記録（請求チャネル②欄が「送信済」に変更 ※DO②とDO⑤は同じスロットを使用）
  → 顧客へ決済リンクメールを自動送信
  ↓
顧客: メール内リンクからクレカ決済 → 決済完了で伝票に入金反映
```

> ボタン押下時点では「決済待ち（pending）」です。処理完了（数秒〜数十秒）後に伝票を再読み込みすると、請求チャネル②欄が「送信済」に変わります。
> ※DO②（配送料）とDO⑤（キャンセル料）は同じ `shipping_fee_*` スロットを使うため、請求チャネルの②欄に表示されます（1伝票につき1つの料金Draft Orderのみ保持）。

### よくある質問

#### Q: 配送料DO②をすでに送信済みですが、キャンセル料も請求したい

本機能はDO②未作成の伝票のみ対象です。DO②送信済み（請求チャネル②が「送信済」）の場合はボタンが表示されません。

> **⚠️ 既知の運用課題（Shopify↔システム間の非連動）:**
> Shopify管理画面でDO②（未入金）を削除しても、**本システム側のステータスは自動で「--」に戻りません**。ShopifyのDraft Order削除と本システムの `shipping_fee_*` ステータスが連動していないためです。
> 現在、DO②送信済みの伝票でDO⑤を請求するには、システム管理者による個別対応（cleanup API `DELETE /bookings/:id/shipping-fee-draft-order` の手動実行、またはDB直接更新）が必要です。この同期は今後の改善予定です（BE側でDraft Order削除webhookを拾って自動リセット、またはFEにDO②取消UIを追加、のいずれかで対応予定）。

#### Q: ボタンが表示されません

以下を確認してください:
- 支払方法がクレジットカード（Shopify）か
- 配送がキャンセルされ、キャンセル料が0円超で入力されているか
- 配送料DO②が未作成（請求チャネル②が「--」）か
- 伝票が「完了」「キャンセル」状態でないか
- 顧客のメールアドレスが登録されているか

#### Q: キャンセル料の金額はどこで決まりますか

各配送のキャンセル料（配送編集モーダルで入力した金額）の合計です。バックエンドが算出するため、金額を送信する必要はありません。
