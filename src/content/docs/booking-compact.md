> **パス:** `/booking-compact`
> **メニュー:** 伝票管理 > 新規予約作成

![貸し出し伝票作成画面](/images/booking-compact.png)

## 概要

レンタル商品の予約伝票を作成・編集する画面です。顧客情報、商品明細、配送情報、料金計算を一元的に管理し、6ステップのワークフローで伝票を完成させます。

## アクセス方法

- サイドバーから: 「伝票管理」>「新規予約作成」をクリック
- 他画面からの遷移:
  - 伝票検索画面から「編集」ボタンで遷移（既存伝票の編集）
  - 予約状況照会から「伝票に追加」リンクで遷移
  - Draft Orderから自動読み込み（`?draft_order_id=xxx` パラメータ付き）
- URL直接: `/booking-compact` または `/booking-compact?id={booking_id}`

## 画面モード

| モード         | 説明               | 切り替え方法                   |
| -------------- | ------------------ | ------------------------------ |
| 新規作成モード | 新しい伝票を作成   | 初期アクセス時                 |
| 閲覧モード     | 既存伝票を表示のみ | 既存伝票を開いた直後           |
| 編集モード     | 既存伝票を編集     | 「編集モードに切り替え」ボタン |

## 操作手順

### 手順1: レンタル期間の設定

1. 「予約種別」で「通常予約」または「展示会予約」を選択
2. 展示会予約の場合、展示会を選択（期間が自動設定される）
3. 通常予約の場合、「開始日」と「終了日」を入力
4. レンタル日数が自動計算されることを確認

**期待される結果:**

- レンタル日数が表示される
- 終了日が開始日より前の場合、警告が表示される

### 手順2: 伝票情報の入力

1. 「支払方法」を選択
   - **現金/クレジットカードの場合:** 「支払予定日」を入力
   - **振込の場合:** 「請求先担当者」を入力
2. 「注文方法」を選択（デフォルト：WEB）
3. **作成担当者・更新担当者**: 保存時にログインユーザーが自動的に設定されます（手動選択不要）

**期待される結果:**

- 支払方法に応じた追加フィールドが表示される
- 振込選択時に請求先住所が登録されていない場合、警告が表示される

### 手順3: 顧客情報の入力

1. 「顧客検索」フィールドに検索キーワードを入力
2. 「検索」ボタンをクリック
3. 顧客選択モーダルで該当する顧客をクリック
   - **Shopifyから同期（#476）**: モーダル内の「🔄 Shopifyから同期」ボタンで最新顧客データをShopifyから取得可能
4. 顧客情報が自動入力されることを確認
5. 必要に応じて追加情報を編集

**期待される結果:**

- 顧客情報が各フィールドに自動入力される
- 顧客コードが設定される

### 手順4: 商品明細の追加

#### 方法A: 商品検索から追加

1. 「商品検索」ボタンをクリック
2. 商品検索モーダルで以下のいずれかの方法で検索:
   - **前方一致検索:** 商品名・SKU・カテゴリ・タグで検索
   - **SKU一括検索:** SKUを改行区切りで複数入力（最大100個）
3. 検索結果テーブルの列:

| 列名     | 説明                                          |
| -------- | --------------------------------------------- |
| 全選択   | 一括選択チェックボックス                      |
| 状況     | 在庫状況（⚪︎/確/仮/△/×）※Issue #438で追加     |
| SKU      | 商品SKUコード                                 |
| 商品名   | 商品の名称                                    |
| カテゴリ | 商品カテゴリ                                  |
| 単価     | 1日あたりのレンタル単価                       |
| 在庫     | Shopify在庫数※Issue #438で追加                |
| 場所     | 在庫場所（tagsから抽出）※Issue #438で追加     |
| 注       | 一般備考（メンテナンス情報）※Issue #438で追加 |
| 特記     | 特記事項（取扱注意）※Issue #438で追加         |

> **列構成（#474）**: 現行システム（@Suite）の商品検索モーダルと同一の列構成に統一済み。

4. 検索結果から商品を選択（チェックボックス）
   - **「追加済み」表示:** 既に明細に追加されている商品（SKU一致）はグレーアウトしチェック不可
   - **キャンセル済みは除外:** キャンセル済みアイテム（`itemStatus === 'cancelled'` または `cancelledAt` 設定済み）は追加済み判定から除外されるため、再度追加可能
5. 「選択した商品を追加」ボタンをクリック

#### 方法B: Draft Orderから追加

1. 顧客選択後、「予約商品から選択」ボタンが表示される
2. ボタンをクリックしてDraft Order商品モーダルを開く
3. 追加する商品を選択
4. 「選択した商品を追加」ボタンをクリック

#### 方法C: その他商品追加

1. 「その他商品追加」ボタンをクリック
2. カテゴリ、商品名、数量、単価などを入力
3. 「追加」ボタンをクリック

**期待される結果:**

- 明細テーブルに商品が追加される
- 金額が自動計算される
- 商品点数と合計金額が更新される

### 手順5: 配送情報の入力

1. 配送情報セクションの「+ 配送追加」ボタンをクリック
2. 配送タイプ（搬入/搬出）を選択
3. 配送日を入力
4. 時間指定がある場合は設定
5. 配送先情報を入力
6. 必要に応じて複数の配送を追加（最大10件）

**期待される結果:**

- 配送情報がテーブルに追加される
- 配送料計が更新される

### 手順6: 保存と確認

1. 入力内容を確認
2. 「保存」ボタンをクリック
3. 保存完了後:
   - **現金/クレジットカード:** 伝票検索画面に自動遷移
   - **振込:** 請求書作成へのリンク付きトーストが表示

**期待される結果:**

- 伝票が保存される
- 伝票番号が割り当てられる
- 適切な画面に遷移する

## 支払方法別の条件分岐

### 現金（cash）/ クレジットカード（credit_card）

| 項目         | 必須     | 説明               |
| ------------ | -------- | ------------------ |
| 支払予定日   | **はい** | 支払い期限日を入力 |
| 請求先担当者 | いいえ   | 表示されない       |

### 振込（bank_transfer）

| 項目         | 必須     | 説明                         |
| ------------ | -------- | ---------------------------- |
| 支払予定日   | いいえ   | 表示されない                 |
| 請求先担当者 | **はい** | 請求書送付先の担当者名を入力 |

**注意:** 振込を選択する場合、顧客に請求先住所（billing_address）が登録されている必要があります。登録がない場合は警告が表示されます。

> **⚠️ 既知の制限（請求先登録導線）**
>
> 振込選択時の請求先セレクターは実装済みですが、伝票作成フロー内に請求先の**新規登録画面**が存在しません。
>
> **現状の登録方法**:
>
> - 顧客管理画面（`/customer-management`）の「請求先」タブから事前登録が必要
> - Shopifyメタフィールド経由でも登録可能（1件のみ）
>
> **解決策**: 伝票作成画面内に請求先新規登録モーダルを追加すれば、インラインで請求先を追加可能です。
> 必要なAPI（`POST /master-data/admin/billing-addresses`）とフォームコンポーネント（`billing-address-form-modal.tsx`）は既に実装済み。
>
> **⚠️ テーマ側の対応も必要**:
>
> - Shopifyテーマ（`/account/addresses`）に顧客向け住所管理画面が存在
> - アカウントページ（タブ3）にも「請求先管理」が表示される
> - Backend `billing_addresses` テーブルと別システムのため、二重管理による混乱を防ぐため非表示化が必要
> - 対応リポジトリ: `ease-rental-shopifytheme`

## 延長料金計算ルール

レンタル期間を延長した場合の追加料金計算ルールです。

### 計算式

```
1日目: 基本料金（100%）
2〜6日目: 基本料金 + (日数-1) × 20%/日
7日目以降: 200% + (日数-6) × 10%/日
```

### 計算例（基本料金 = 1,000円の場合）

| 日数  | 計算式        | 金額    | 増分         |
| ----- | ------------- | ------- | ------------ |
| 1日目 | 1,000         | 1,000円 | -            |
| 2日目 | 1,000 + 200   | 1,200円 | +200円 (20%) |
| 3日目 | 1,000 + 400   | 1,400円 | +200円 (20%) |
| 4日目 | 1,000 + 600   | 1,600円 | +200円 (20%) |
| 5日目 | 1,000 + 800   | 1,800円 | +200円 (20%) |
| 6日目 | 1,000 + 1,000 | 2,000円 | +200円 (20%) |
| 7日目 | 2,000 + 100   | 2,100円 | +100円 (10%) |
| 8日目 | 2,000 + 200   | 2,200円 | +100円 (10%) |

### ポイント

- **1〜6日目:** 前日比で基本料金の20%ずつ増加
- **7日目以降:** 6日目の金額（基本料金の200%）から、前日比で基本料金の10%ずつ増加

## 予約ステータス（BookingStatus）

| ステータス      | 説明               |
| --------------- | ------------------ |
| PROCESSING      | 処理中（初期状態） |
| BILLING_PENDING | 請求待ち           |
| PAYMENT_PENDING | 入金待ち           |
| COMPLETED       | 完了               |
| CANCELLED       | キャンセル済み     |

新規作成時のデフォルトステータスは `PROCESSING` です。

## 便利機能

### キーボードショートカット

| ショートカット | 機能     |
| -------------- | -------- |
| Ctrl + S       | 保存     |
| Ctrl + N       | 商品追加 |

### 一括設定機能

「一括設定」ボタンから以下の設定を一括で行えます。

| タブ       | 設定項目                         |
| ---------- | -------------------------------- |
| 期間       | 開始日、終了日、数量、値引き     |
| キャンセル | キャンセル日、キャンセル料、メモ |
| メモ       | メモ（全明細に同一メモを設定）   |

> **一括キャンセル時の自動計算（#450）**: キャンセルタブで「保存」時、Backend `/bookings/:id/items/cancel` APIを呼び出し、キャンセル料が自動計算されます。手動入力値も送信可能ですが、Backend側で計算結果が優先される場合があります。

### 仮押さえ機能

在庫を一時的に確保する機能です。確定予約の依頼が入った場合は、仮押さえ顧客に確認後、すぐに確定予約にならない場合は確定予約を優先します。

- **時間制限:** なし（優先度ベース）
- **表示:** ステータス列に「仮」と表示
- **操作:** ステータス列のトグルボタンで設定/解除

### 行複製機能

明細行の右端にある複製ボタンで、同じ内容の行をコピーできます。

- 複製された行は新しいIDが割り当てられます
- 在庫ステータスはリセットされます（PENDING/⚪︎）

### 仮予約の自動管理（Backend Cron）

未入金の仮予約に対して、Backendのcronジョブが毎日自動でリマインダー送信と自動キャンセルを実行します。

| 項目           | 設定                                                     | 環境変数                          |
| -------------- | -------------------------------------------------------- | --------------------------------- |
| Cron実行       | 毎日 02:00 JST                                           | -                                 |
| リマインダー①  | 開始日9日前に送信（初回案内）                            | -                                 |
| リマインダー②  | 開始日8日前に送信（2回目）                               | -                                 |
| **最終催促**   | **開始日7日前に送信（自動キャンセル前日）**              | -                                 |
| 自動キャンセル | 開始日**6日前**に自動キャンセル                          | `DRAFT_AUTO_CANCEL_DAYS_BEFORE=6` |
| 対象           | 未入金の伝票（PROCESSING/PRICE_PENDING/BILLING_PENDING） | -                                 |

**自動管理フロー（例: 開始日 4/8 の場合）:**

```
伝票作成（PROCESSING）
  │
  ├─ 3/30（9日前）: リマインダー①「仮予約を受け付けました」
  ├─ 3/31（8日前）: リマインダー②「お支払いをお願いします」
  ├─ 4/1（7日前）: 最終催促「明日自動キャンセルされます」← NEW
  ├─ 4/2（6日前）: 自動キャンセル（在庫解放）
  │
  └─ 入金済みの場合: 自動管理対象外
```

> **対象外:** 以下は自動キャンセルされません。
>
> - 顧客に「銀行振込可」タグがある場合（Issue #463）
> - `source: backend_app` の管理画面作成予約（Issue #525）
> - Issue #787: Flow B - 長期間オープンのDraftOrder監視（03:00 JST）

> **未実装:** 最終催促メール（開始日7日前）は Backend Issue で対応予定。

## 備考

- Draft Orderから遷移した場合、顧客情報と商品明細が自動的に読み込まれます
- 既存伝票を開いた直後は「閲覧モード」になります。編集するには「編集モードに切り替え」ボタンを押してください
- 振込支払の場合、請求書の作成が別途必要です
- 明細の在庫ステータスが「仮」「△」「×」の場合、保存時に確認ダイアログが表示されます
- 前払金は保存前でも記録できます（ローカル状態で保持され、保存時に一緒に送信されます）
