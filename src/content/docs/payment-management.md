## 概要

支払方法が「店頭支払」または「銀行振込」の未入金伝票を検索し、入金処理を行います。振込（請求書）の入金処理は「請求書・領収書管理」画面で行います。

> **検索の初期状態（#1219）:** 初期表示では「店頭支払」のみがチェック済みで、銀行振込の未入金伝票は検索結果に含まれません。銀行振込も含めて検索する場合は、検索フィルターの「銀行振込」チェックボックスをオンにしてください。

画面は2つのタブで構成されており、それぞれ異なる目的を持ちます：

| タブ | 名称 | 対象 | 主な機能 |
| ---- | ---- | ---- | -------- |
| Tab 1 | 店頭・振込 未入金 | 店頭支払・銀行振込の未入金伝票 | 検索・選択・入金処理（モーダル）・CSV出力・一括再請求 |
| Tab 2 | クレカ後発料金（DO②/DO③） | クレジットカード後発料金の未入金 | 読み取り専用トラッキング・Shopifyリンク |

**対象となる支払方法:**

- 店頭支払（`store_payment`, `cash`, `credit_card`）— 店頭での現金・カード払い
- 銀行振込（`bank_transfer`）

## アクセス方法

- サイドバーから: **請求・入金 > 未入金伝票・現金入金**
- URL直接: `/payment-management`

再請求された伝票には、伝票番号の横にオレンジ色の **「再請求」** バッジが表示されます。バッジにマウスカーソルを合わせると、再請求回数を確認できます（例: 「再請求回数: 2回」）。

### 1件ずつの「入金処理」ボタン

各伝票行の右端（操作カラム）に、青色の **「入金処理」** ボタンがあります。クリックすると入金処理モーダルが開き、1件ずつ処理を行います（[入金処理モーダル](#入金処理モーダル)で後述）。

> **Tip（#1219）:** 現在は一覧からのモーダル起動のみで、複数伝票の一括入力フォームは廃止されました。チェックボックスによる選択はサマリー（選択中・選択合計）確認用とグルーピング表示用に残っていますが、入金処理は1件ずつモーダルから行います。

### 表示件数

一覧の下部のセレクトで1ページあたりの表示件数を変更できます。

| 選択肢                     | 説明             |
| -------------------------- | ---------------- |
| 20件ずつ表示（デフォルト） | 標準表示         |
| 40件ずつ表示               |                  |
| 60件ずつ表示               |                  |
| 90件ずつ表示               |                  |
| 120件ずつ表示              | 大量処理時に推奨 |

表示件数を変更すると自動的に1ページ目に戻ります。

### ページネーション

| 操作       | 説明                            |

| 前へ       | 前のページへ移動                |

## 入金処理モーダル

未入金伝票一覧の伝票行にある **「入金処理」** ボタンをクリックすると、入金処理モーダルが開きます（#1219 で一括フォームからモーダル方式に変更）。1件ずつ処理を行います。

### モーダルに表示される情報

- 伝票番号・貸出先名・未入金額（確認用）

### 入力項目

> **参照番号・備考欄は廃止されました（#1219）。** 現金・カード払いでは不要のため、入金日と処理担当者のみ入力します。

| 項目       | 種類     | 説明                                 | 必須 |
| ---------- | -------- | ------------------------------------ | ---- |
| 入金日     | 日付     | 入金があった日付（デフォルト: 本日） | Yes  |
| 処理担当者 | セレクト | 処理を行うスタッフ                   | Yes  |

### 実行ボタン

モーダル下部に3つのボタンがあります。入金日・処理担当者の両方が入力されるまでボタンは無効（グレーアウト）です。

| ボタン             | 色         | 動作                                                                 |
| ------------------ | ---------- | -------------------------------------------------------------------- |
| キャンセル         | グレー     | モーダルを閉じる（処理なし）                                         |
| 入金のみ           | 青枠       | 入金処理のみ実行。領収書は発行しない                                 |
| 入金+領収書発行    | 緑         | 入金処理後、**自動で領収書を発行**（確認ダイアログなし・#1219）      |

> **💡 領収書の自動発行（#1219）:** 「入金+領収書発行」を選ぶと、入金成功後に領収書が自動発行されます（従来のような「領収書を発行しますか？」の確認ダイアログは出ません）。発行に失敗した場合はエラートーストで通知されます。

### 選択中伝票のサマリー（一覧上部）

チェックボックスで伝票を選択すると、一覧上部のサマリーに「選択中」「選択合計」が表示されます。選択は顧客ごとのグルーピング表示や金額確認用に残っていますが、**入金処理はモーダル経由で1件ずつ行う**ため、選択状態自体は入金処理の実行条件ではありません。

### 入金処理後の動き

入金処理が完了すると、以下の変化が自動的に行われます：

#### EASEシステム内の更新（即時）

| 更新対象     | 変更内容                                       |
| ------------ | ---------------------------------------------- |
| 伝票の支払ステータス | `未入金` → `入金済み（paid）`            |
| 入金記録     | `payment_records` テーブルに記録が作成される   |
| 請求書       | 紐づく請求書の支払ステータスが `入金済み` に更新、未収額が `0` になる |
| 処理済み伝票 | 一覧から自動的に除外される                     |

> **⚠️ 入金済みでも未入金一覧に再表示されるケース（Issue #2249）:**
> 一度全額入金（`paid`）となった伝票でも、**返却時の延長料金などで後から請求金額が増えた** 場合、システムが支払ステータスを `partially_paid`（一部入金）に自動で差し戻し、未入金一覧に**再表示**されることがあります。これは二重請求を防ぐための正常な挙動です（増加分を再度入金処理してください）。

#### Shopify自動連携（非同期・最大1分後）

Shopify注文が紐づいている伝票（銀行振込でShopify Draft Order→Order変換済みのもの）は、入金記録が**自動でShopifyに送信**されます。

| 項目 | 内容 |
| ---- | ---- |
| 連携タイミング | 入金処理後、**最大1分以内**に自動実行（バックエンドのcronワーカーが毎分処理） |
| Shopifyへの送信内容 | 注文ID、入金金額、支払方法名（例: 「銀行振込」）、入金日 |
| Shopify側の表示 | 注文詳細画面に「手動決済」として記録される |
| 手動操作 | **不要** — Shopify管理画面で消し込み操作は必要ありません |

> **Note:** Shopify連携は非同期のため、入金処理直後にShopify管理画面を開いてもまだ反映されていない場合があります。最大1分後に再確認してください。連携に失敗した場合は自動リトライ（最大5回）が行われます。

## 一括再請求機能

期限超過の未入金伝票がある場合、一括で再請求（請求書の再発行）ができます。

### 表示条件

支払予定日を過ぎた未入金伝票（`daysOverdue > 0`）が1件以上ある場合、一覧の上部にオレンジ色の警告バーが表示されます。

### 操作手順

1. 警告バーの「🔄 一括再請求」ボタンをクリック
2. 確認ダイアログが表示されます:
   - 「期限超過のN件の請求書を一括再請求しますか？」
   - 「※新しい請求書番号で再発行されます。」
3. **OK** をクリックすると実行

### 実行結果

| パターン | トーストメッセージ |
| -------- | ------------------ |
| 全件成功 | 「5件の再請求が完了しました」 |
| 一部失敗 | 「3件の再請求が完了しました（2件失敗）」 |
| 全件失敗 | エラーアラートが表示 |

再請求後、一覧が自動的に更新されます。再発行された伝票には「再請求」バッジが表示されます。

## Tab 2: クレカ後発料金（DO②/DO③）

> **情報バナー:** 「クレジットカード後発料金（DO②配送料 / DO③延長・追加料金）の未入金トラッキング。Shopifyのカード決済で完結するため入金処理は行いません。督促メールは自動送信されます（入金確認まで表示）。」

### 概要

このタブは、クレジットカード決済の顧客に対して**レンタル後**に発生した未入金の追加料金をトラッキングする**読み取り専用**の画面です。

**対象となる料金:**

| 種別 | 名称 | 説明 |
| ---- | ---- | ---- |
| DO② | 配送料 | 配送時に発生した送料。Shopify Draft Orderで請求済み |
| DO③ | 延長・追加料金 | 返却時の延長料や追加料金。Shopify Draft Orderで請求済み |

> **重要:** このタブでは**入金処理は行いません**。クレジットカード決済はShopifyのDraft Order経由で完結するため、支払い状況は自動的に更新されます。バックエンドのcronが定期的にShopifyから支払い状況を取得し、`billing_status` を更新します。

### フィルター

| 項目 | 種類 | 選択肢 |
| ---- | ---- | ------ |
| 料金種別 | ドロップダウン | すべて / DO②配送料 / DO③延長・追加料金 |

### テーブルカラム

| # | カラム | 説明 |
|---|--------|------|
| 1 | 伝票No. | 伝票番号（クリックで伝票ページに遷移）。伝票番号がない場合はハイフン表示 |
| 2 | 貸出先 | 顧客名とメールアドレス（2行）。未設定の場合はハイフン |
| 3 | 料金種別 | バッジで表示: DO②配送料（水色）/ DO③延長/追加（紫色） |
| 4 | 未入金額 | 未入金の金額。金額が確定できない場合は **「金額未解決」** とグレー表示 |
| 5 | 基準日 | DO②=配送日 / DO③=請求日（YYYY/MM/DD形式） |
| 6 | Shopify | 「下書き注文 ↗」リンク（Shopify管理画面のDraft Orderページを新しいタブで開く）。Draft Orderがない場合はハイフン |

### ユーザーができること

| 操作 | 説明 |
| ---- | ---- |
| 料金種別でフィルター | ドロップダウンでDO②/DO③を絞り込み |
| 伝票番号をクリック | 伝票詳細ページ（`/booking-compact`）に遷移 |
| 「下書き注文」リンクをクリック | Shopify管理画面の該当Draft Orderを新しいタブで開く |
| ページネーション | 前へ/次へで移動（1ページ50件） |

### 督促メールについて

督促メールは**バックエンドのcronにより自動送信**されます。手動で送信ボタンを押す必要はありません。入金が確認される（Shopifyの支払いステータスが更新される）と、該当件がこの一覧から自動的に消えます。

## 操作手順

### 手順1: 未入金伝票の検索

1. 検索条件を入力する
   - 担当者で絞り込む場合: 「担当者」フィールドに担当者名を入力
   - 支払方法でフィルタリング: 「店頭支払」「銀行振込」のチェックボックスを選択（初期状態は「店頭支払」のみオン・#1219）
   - 日付範囲で絞り込む場合: 「支払予定日」「貸出年月」「返却年月」のFrom/Toを入力
2. 「検索」ボタンをクリック
3. 検索結果が一覧に表示される
4. サマリーで総件数・未入金合計を確認

**表示件数の調整:**

- 処理件数が多い場合は表示件数セレクトで 60〜120件を選択
- ページ移動が不要になり、一括での確認・選択が容易になる

### 手順2: 入金処理対象の確認

1. 検索結果から入金処理対象の伝票を確認する
   - 必要に応じてチェックボックスで選択すると、サマリーの「選択中」「選択合計」で金額を確認できる（#1219 で入金処理はモーダル経由となり、選択は確認用）
   - 顧客ごとのグルーピング表示で、同一顧客の伝票をまとめて確認可能
2. 対象の伝票行の **「入金処理」** ボタンをクリック

### 手順3: 入金処理の実行（モーダル）

1. モーダルが開いたら、以下を入力する:
   - **入金日** （必須）: 実際に入金された日付。デフォルトは本日
   - **処理担当者** （必須）: ドロップダウンからスタッフを選択
2. 目的に応じてボタンを選ぶ:
   - **「入金のみ」** （青枠）: 入金処理だけ行う
   - **「入金+領収書発行」** （緑）: 入金処理後に領収書を自動発行（確認ダイアログなし・#1219）
3. 処理完了後、成功トーストが表示され、処理済みの伝票は一覧から除外される

> **Tip:** 入金日・処理担当者が未入力の間は「入金のみ」「入金+領収書発行」ボタンは無効（グレーアウト）します。両方入力するとボタンが有効になります。

### 手順4: CSV出力

1. 検索を実行して結果を表示する
2. 「CSV出力（N件）」ボタンをクリック
3. `未入金一覧_{YYYY-MM-DD}.csv` がダウンロードされる

## 業務ロジック

### 支払方法の対応関係

| 画面表示 | システム内部値                         | 説明                                      |
| -------- | -------------------------------------- | ----------------------------------------- |
| 店頭支払 | `store_payment`, `cash`, `credit_card` | 店頭での現金・カード払い（3値を一括表示） |
| 銀行振込 | `bank_transfer`                        | 銀行振込払い                              |

> **注意:** `store_payment` / `cash` / `credit_card` はすべて「店頭支払」として扱われます。検索チェックボックスでは1つのトグルで3値を一括指定します。

### 前払い金の扱い

- `prepaid_amount` が設定されている伝票は、既に一部金額を受領済みであることを示す
- CSV出力時も前払い金額が含まれる
- `未入金額 = 合計金額 - 前払い金額`（バックエンドで計算済み）

### 担当者フィルタ

- 担当者名を入力すると、該当する担当スタッフが割り当てられた予約のみが表示される（#1219 で「担当者コード」から「担当者（名）」に表記変更）
- 担当者が未割り当ての伝票は、フィルタに引っかからず除外される

### 入金処理の排他制御

- バックエンドで行レベルロック（`SELECT FOR UPDATE`）を使用し、二重入金を防止しています
- 画面の入金処理は**全額入金のみ**に対応しています（部分入金の入力欄はありません）。ただし上記 #2249 のとおり、システム側で `partially_paid`（一部入金）状態になることはあります
- すでに「入金済み」「返金済み」の伝票に対する入金処理はエラーになります

### Shopify連携の仕組み

入金処理後のShopify連携は以下の仕組みで動作します：

```
入金処理実行
  ↓ (即時)
EASE DB更新（bookings / payment_records / invoices）
  ↓ (非同期・最大1分)
ShopifySyncWorker がジョブを取得
  ↓
Shopify GraphQL `orderCreateManualPayment` 実行
  ↓
Shopify側に「手動決済」として記録
```

- **連携対象:** `shopify_order_id` が設定されている伝票のみ
- **リトライ:** 失敗時は指数バックオフ（1分→5分→15分→1時間→6時間）で最大5回リトライ
- **Shopify側の操作:** 不要。自動で入金記録が反映されます

## 注意事項

- この画面は「店頭支払」「銀行振込」の未入金伝票が対象
- 「振込（請求書払い）」の伝票は請求書作成 → 入金処理のフロー（[請求一覧・入金処理](/invoices-list)）
- 入金処理はモーダルで1件ずつ行います（#1219 で一括入力フォームは廃止）
- 画面の入金処理は全額入金のみ（部分入金の入力欄はありません）
- 入金処理後のShopify連携は自動（手動操作不要）。最大1分で反映
- Tab 2（クレカ後発料金）は読み取り専用。入金処理はShopify側で自動完結する
- 一括再請求機能: 期限超過の伝票に対して新しい請求書番号で再発行可能
- 銀行振込伝票の請求書は顧客の請求先メール（`billing_email`）宛てに送付されます。送付先がズレている場合は [顧客管理 > 請求先管理](/customer-management/) で修正してください
