> **💡 運用者向け:** お客様の決済方法（クレカ前払い・クレカ後払い・銀行振込・店頭現金）によって、**伝票の作り方・請求書の発行タイミング・返金の方法**が異なります。このページでは「どんなケースでどう伝票を作成するか」を一覧表で整理しています。迷ったときはこの表を参照してください。

## 決済方法の分類

| 決済方法 | 条件 | お支払いのタイミング |
|---|---|---|
| **クレカ前払い** | クレカ × 店頭受取 × カートで「今すぐ払う」を押した | カートで**その場でカード決済が完了** |
| **クレカ後払い** | クレカ × 配送、または店頭受取で「今すぐ払う」を押さなかった | **金額が確定してから**、決済リンク付きメールでカード決済 |
| **銀行振込** | 「銀行振込可」の顧客のみ | 返却後に**請求書を発行** → 振込 → 入金登録 |
| **店頭現金** | 現金・PayPay・店頭でのカード等 | 返却時の金額確定後に**店頭で受け取って**入金登録 |

> 「クレカ後払い」は 2026-07 に基本化されました（以前は前払い強制）。店頭受取のクレカは**デフォルト後払い**で、「今すぐ払う」ボタンを押した場合のみ前払いになります。

## 伝票作成マトリクス（決済方法 × 状況）

| 何を支払うか | クレカ前払 | クレカ後払(店頭受取) | クレカ後払(配送) | 銀行振込 | 店頭現金 |
|---|---|---|---|---|---|
| **本体（レンタル料＋配送料）** | カートで即時決済 | 前日に自動でカード請求 | 前日自動／手動「金額確定」でカード請求 | 伝票作成のみ（支払いは後日の請求書） | 伝票作成のみ（店頭で受け取る） |
| **配送料** | 別のカード請求 | （配送なし） | 本体と一緒に請求 | 本体と一緒に請求書へ | 本体と一緒に店頭で |
| **追加料金（延長・破損）** | 別のカード請求 | 金額確定後にカード請求 | 金額確定後にカード請求 | 伝票に加算し請求書で回収 | 伝票に加算し店頭で回収 |
| **追加した商品** | 別のカード請求 | 別のカード請求 | 別のカード請求 | 伝票に直接追加 | 伝票に直接追加 |
| **配送キャンセル料** | 別のカード請求 | 本体と一緒に請求 | 本体と一緒に請求 | 伝票に計上し請求書で回収 | 伝票に計上し店頭で回収 |
| **返金** | 管理画面から（カード返金が自動） | 同左 | 同左 | 記録のみ（振込で返金） | 記録のみ（現金で返金） |

> **追加料金をカードで回収したい場合（銀行振込・店頭精算の伝票）**: 下記「[追加料金を後からカードで回収する](#追加料金を後からカードで回収する銀振店頭精算伝票)」の手順で Shopify の決済リンクを使えます。**クレカ伝票で店頭の現金・PayPay等を受け取る場合**は「[クレカ伝票のお客様が店頭で現金・PayPay等で支払う場合](#クレカ伝票のお客様が店頭で現金paypay等で支払う場合)」を参照してください。

## 追加料金を後からカードで回収する（銀振・店頭精算伝票）

店頭で精算済み（現金・PayPay・店頭カード）や銀行振込の伝票で、**返却後に発生した追加料金（延長料・損料など）をお客様がカードで支払いたい**場合の手順です。

> クレカ伝票（Shopify決済）の場合は、伝票画面の**追加請求（DO③）**が決済リンク付きメールを自動送信するため、この手順は不要です。

:::warning
**暫定運用です。** 追加入金導線の統一は BE #2762 で検討中です。システム側の導線が確定したらこのページは更新されます。
:::

### 手順

1. **Shopify管理画面** → 販売 → 下書き注文 →「下書き注文を追加」
2. 顧客を指定し、**カスタム品目**で「延長料金（伝票番号 B…）」などの品目名と金額を入力
3. 「請求書を送る」でお客様に決済リンク付きメールを送信（リンクをコピーしてメール・電話で案内してもOK）
4. お客様がカードで決済
5. **EASE管理画面「未入金一覧・入金処理」で対象伝票に手動入金登録**（Shopifyでの入金はEASE伝票へ自動反映されません）

### 注意事項

- **品目は必ず「カスタム品目」のみにする**: レンタル商品（商品マスタの品目）を入れると、決済完了時にEASEが新規伝票として自動取り込みし、在庫を二重に押さえる恐れがあります
- マイアカウントの「未払い」には表示されません（EASE発行の追加請求ではないため）
- 決済方法がクレカの伝票には使わない（伝票画面の「追加請求」を使う）

## クレカ伝票のお客様が店頭で現金・PayPay等で支払う場合

クレジットカード（Shopify決済）の伝票で、お客様が返却時に店頭で**現金・PayPay等**で支払いたいと言うことがあります。EASEの入金画面はクレカ伝票の入金登録を受け付けない設計（Shopify決済との二重計上防止）のため、**Shopify側で支払いを完了**させます。EASEへの入金反映は自動です。

### 手順

1. Shopify管理画面で該当の伝票を開く
   - 追加料金の場合: EASEの「追加請求」で作成された**下書き注文**（販売 → 下書き注文）
   - 本体分の場合: 先にEASEで金額確定（Shopifyへ送信）を行い、Shopify側の金額を確定額に合わせてから
2. 「支払いを受け取る」で**現金等の手動決済方法**を選んで支払いを完了する（金額は変更しない）
3. 完了すると自動で連携し、**伝票が入金済みになる**（EASEでの入力作業は不要）。領収書も自動発行（お支払い方法の記載は無いため問題なし）
4. EASE側で必要な手動作業は、**伝票備考に実態を記録するのみ**（例: 「延長料は店頭現金で受領」）

### 注意事項

- EASEの伝票上は「Shopify（クレカ）」扱いのままのため、**決済手段別の売上集計ではクレカに計上**されます。実態は伝票備考で担保してください（実際の入金方法はShopify注文側に記録が残ります）
- 事前にShopifyの「手動決済方法」（現金など）が設定されている必要があります（未設定の場合はShopify設定で追加）
- この扱いを含む入金導線の統一は BE #2762 で検討中です

## ライフサイクル（共通）

```
1. カート投入・伝票作成（DO①）
2. 前営業日18時まで: お客様は商品追加/削除可能
3. レンタル開始前日: 請求書発行 → 伝票close → 以降の追加は別伝票
4. 当日キャンセル: システム上不可（伝票close済・電話/メールで手動対応）
5. レンタル期間
6. 返却: 延長/破損等の金額確定
7. 追加料金があれば、クレカはカードで・それ以外は伝票に加算して回収
8. 決済完了 → 完了
```

> **伝票closeとは**: 請求書が発行されて金額が確定した状態。これ以降、商品の追加は別伝票（DO④）に分離され、当日キャンセルも不可になります。店頭現金払いは対象外（即時決済のため前日請求が発生しない）。

## 返金フロー（重要）

### 返金は必ずEASE管理画面から行う

:::warning
**Shopify admin で直接返金しないでください。** EASE に記録が残らず、顧客への請求表示と実際の返金がズレます。
:::

| 決済方法 | 返金方法 | Shopify連携 |
|---|---|---|
| **クレカ**（前払/後払） | EASE管理画面「返金」ボタン → Shopify `createRefund` 自動呼出 | ✅ 連携（1アクションで完結） |
| **銀行振込** | EASE管理画面で `refund_method=bank_transfer` で記録のみ | ❌ 連携なし（オフラインで振込返金後、EASEに記録） |
| **店頭現金** | EASE管理画面で `refund_method=cash` で記録のみ | ❌ 連携なし（現金で返した後、EASEに記録） |

### 万が一 Shopify admin で直接返金してしまった場合

EASE 側には記録されないため、**EASE管理画面でも手動で返金記録を入力**する必要があります（手動2度手間）。これを避けるため、返金は常に EASE 管理画面から行ってください。

### 過払い返金（商品削除等）

クレカ決済済み伝票で商品削除・価格減額があった場合、過払い分（`paid_amount − total_amount`）の返金は `POST /bookings/:id/refund-overpayment` で半自動処理できます。

### 二重決済の検知

振込入金済み伝票に顧客がクレカ決済してしまった場合、EASE が `double_payment_suspected` で警告を出します。自動返金しないため、スタッフが手動で返金処理を行ってください。

## 📌 クレカ前払いキャンセル時の返金フロー（具体例付き）

クレカ前払い（カート投入時に「今すぐ払う」で即時決済済み）の伝票をキャンセルした場合、**キャンセルと返金は別ステップ**です。キャンセルしても自動では返金されないため、スタッフが別途「返金を記録」を行う必要があります（7/23定例 B項）。

### 返金額の計算式

```
返金額 = お客様が支払った金額（paid_amount） − キャンセル料（cancellation_fee）
```

- 返金額が **0以下** の場合 → 返金不要（キャンセル料が支払額を上回る・追加請求の可能性）
- 返金額が **0より大きい** 場合 → その金額を「返金を記録」で処理

### 具体例

#### パターン1: 部分キャンセル料（差額返金）

| 項目 | 金額 |
|---|---|
| お客様の支払額（paid_amount） | ¥10,000 |
| キャンセル料（cancellation_fee） | ¥5,000 |
| **返金額** | **¥5,000** |

**操作ステップ:**
1. 伝票をキャンセル（`cancelBooking`）→ キャンセル料 ¥5,000 が計上される
2. **別途**「返金を記録」ボタン → 返金額 ¥5,000 を入力
3. EASE が Shopify の返金API（`refundCreate`）を自動呼出 → **クレジットカードに ¥5,000 返金**
4. 完了（EASE + Shopify 両方に記録・ズレなし）

#### パターン2: キャンセル料なし（全額返金）

| 項目 | 金額 |
|---|---|
| お客様の支払額 | ¥10,000 |
| キャンセル料 | ¥0（規定日前・または全額免除） |
| **返金額** | **¥10,000** |

→ 「返金を記録」で ¥10,000 を入力 → Shopify が全額返金。

#### パターン3: キャンセル料が支払額を上回る（返金なし・追加請求）

| 項目 | 金額 |
|---|---|
| お客様の支払額 | ¥10,000 |
| キャンセル料 | ¥15,000 |
| **返金額** | **¥0**（−¥5,000 = 返金不要・¥5,000 追加請求） |

→ 返金は不要。¥5,000 の差額は追加請求（DO③ または調整項目）で回収。

### ⚠️ 「手動2度手間」とは

:::warning
**キャンセル ≠ 自動返金。** クレカ伝票をキャンセルしても、システムは**自動では返金しません**。スタッフが別途「返金を記録」を操作する必要があります（2ステップ目）。これが「手動2度手間」の意味です。
:::

| ステップ | 操作 | 自動か |
|---|---|---|
| ①キャンセル | 伝票のキャンセル操作（キャンセル料計上） | スタッフ手動 |
| ②返金 | 「返金を記録」ボタン（Shopify refundCreate 自動呼出） | スタッフが②を押す必要あり・押せばShopify返金は自動 |

> **銀行振込の場合**: システム内で完結（返金記録のみ・Shopify連携なし）。クレカのような「Shopifyへの返金API呼出」は発生しません。

:::dev

## 技術詳細: Draft Order 番号体系

| DO | 用途 | mirror カラム | 作成メソッド |
|---|---|---|---|
| **DO①** | 本体（レンタル料＋配送料） | `shopify_draft_order_gid` / `shopify_order_id` | cart / confirmAmountForDeferredCreditCard / confirmShippingFeeForDeferredCreditCard |
| **DO②** | 配送料（前払いクレカのみ） | `shipping_fee_*` | createShippingFeeDraftOrder |
| **DO③** | 追加料金（延長/破損） | `additional_fee_*` / `additional_fee_billings` 子テーブル | createAdditionalFeeDraftOrder |
| **DO④** | 追加商品 | `product_addition_*` | createProductAdditionDraftOrder |
| **DO⑤** | 配送キャンセル料（前払いクレカのみ） | `cancellation_fee_*` | createCancellationFeeDraftOrder |

## 伝票closeの2種類

| 種類 | トリガー | 効果 |
|---|---|---|
| **hard close** | 本体のカード決済が完了（Shopify で注文化） | 本体への金額追加は不可。追加系はすべて別のカード請求に |
| **soft close** | 後払いクレカで金額が確定（前日請求のセットを含む・支払いはまだ） | 商品の追加・削除はロック。追加商品は別のカード請求へ |
