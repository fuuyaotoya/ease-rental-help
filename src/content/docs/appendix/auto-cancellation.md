> **💡 運用者向け:** カートから作られ、未払いのまま一定時間が経った予約は、在庫を空けるため自動キャンセルの対象になります。目安は135分です。銀行振込の伝票（未確定も含む）、後払い伝票、管理画面で手動作成した仮予約は、この自動キャンセルの対象外です。レンタル開始日が近い未払い伝票は、スタッフが確認してください。

:::dev
> **出典:** BE #1772 調査結果（2026-05-23）+ #1944（銀行振込保護）+ #2072/#2073（仮予約自動失効 cron 廃止）+ #2284/#2330（deferred-checkout 除外）+ #2407（開始日基準 auto-cancel 停止）+ #2692（開始日基準ジョブ撤去）

## 概要

Shopify テーマ経由（カート）で作成された予約のうち、決済が完了しないまま放置された Draft Order は**自動的にキャンセル**されます。これにより、在庫の長期ロックを防ぎ、新規予約を受け付けられる状態に戻します。

ただし、**入金や返却を待つべき予約は自動キャンセルから保護**されます（#1944/#2284/#2330）。また、管理画面で手動作成した仮予約は自動失効しません（#2072/#2073 で仮予約失効 cron を廃止・スタッフ手動キャンセルのみ）。

## 自動キャンセルの主体

| cron | 頻度 | 役割 | 主な対象 | 現状 |
|------|------|------|---------|------|
| **`draft-order-cleanup`**（①）| 5分毎（既定135分で失効）| 未決済 Draft Order の短期 hold 解放（カート落ち）| 未決済の cart 経由予約 | **稼働中** |
| **`draft-booking-lifecycle`**（旧③）| 毎日 02:00 JST | 開始日基準の支払期限失効（開始6日前）| 開始日が近づいた未決済予約 | **#2692 で撤去済み** |

> **#2407・#2692:** 開始日基準の自動キャンセルと、その前段の督促メールは停止後にコードから撤去されました。現在稼働している自動キャンセルは **①（135分・放置カート回収）のみ**です。

> 旧③は開始日基準の処理でした。①の放置カート回収とは別の処理です。

## キャンセル対象（保護対象外）

| 条件 | 値 |
|------|---|
| 伝票ステータス | `DRAFT` / `PROCESSING` / `BILLING_PENDING` / `PAYMENT_PENDING`。支払いは未入金または未設定 |
| 予約ソース | 主に `cart`（Shopify テーマ経由）。`backend_app`（管理画面手動作成）は対象外 |
| 支払方法 | `bank_transfer` または顧客の「銀行振込可」タグで保護される伝票は、未確定も含めて対象外（#1944） |
| 決済方法の性質 | 先払い（`pay_now=true`）。**後払い（deferred-checkout：配送 or pickup×`pay_now=false`）は対象外**（#2284/#2330・返却後決済のため）|
| キャンセル理由 | `Draft Order expired (unpaid)` |

## 対象外のケース（保護される予約）

以下の予約は**自動キャンセルされません**（入金や返却を待つ・または手動管理のため）:

| 伝票種別 | 理由 | 対応 issue |
|---------|------|-----------|
| **銀行振込**（`銀行振込可`タグ保有 or `payment_method=bank_transfer`）| 入金を待つため、未確定も含めて短期の自動キャンセルから除外 | #1944（#1319 で誤削除→復活）|
| **後払い伝票**（deferred-checkout：クレカ×配送 or クレカ×pickup×`pay_now=false`）| 返却後に決済するため、①②の自動キャンセルから除外。督促メールも skip | #2284/#2330 |
| **管理画面の仮予約**（`source=backend_app`・`confirm_status=TENTATIVE`）| ①③は `source:{not:'backend_app'}` で元々到達しない。仮予約失効 cron（旧 `tentative-reservation-cleanup`）は #2072/#2073 で**廃止**（スタッフ手動キャンセルのみ・`tentative_expires_at` も付与しない）| #2072/#2073 |
| **社内確保**（`booking_type=internal_hold`・[詳細](/internal-hold/)）| 支払いを前提としない在庫確保用の種別のため対象外。出荷しないまま期間が過ぎた伝票は、毎日早朝の自動処理が期限切れ分を自動「**完了**」させる（自動キャンセルではない）| #3030 |
| 既に AMOUNT_CONFIRMED / COMPLETED の伝票 | キャンセル対象ステータスではない | — |
| Shopify の下書き注文が `invoice_sent` | 請求メール送信済みの下書き注文は、状態が取得できた場合に除外 | #175 |

## 自動処理フロー

```
Shopify でカート → Draft Order 作成（決済前）
   ↓
   ↓ 顧客が支払い操作を行わず放置
   ↓
   ↓ 135分経過（draft-order-cleanup）
   ↓
Backend が検知（銀行振込 / 後払い / 管理画面仮予約は skip）
   ↓
booking.status = CANCELLED
booking.cancellation_reason = "Draft Order expired (unpaid)"
   ↓
在庫ロック解放（releaseInventoryBatch）
Shopify の Draft Order を削除
```

2026-05-22 時点のテスト環境より:

| 伝票No. | 作成日 | キャンセル日 | レンタル開始日 | 支払方法 |
|---------|--------|------------|--------------|---------|
| B260522028 | 5/22 | 5/22 | 5/22 | 銀行振込 |
| B260522012 | 5/22 | 5/22 | 5/29 | クレカ |
| B260521017 | 5/21 | 5/21 | 5/23 | クレカ |
| B260521013 | 5/21 | 5/21 | 5/22 | 銀行振込 |

> 直近5/18〜5/22まで毎日キャンセルが発生しており、ジョブ・Webhook が安定稼働していることを示しています。
> 上の例は2026年5月の記録です。現行の短期処理は、未確定（DRAFT）段階でも銀行振込を対象外にします。
>
> **#2407（2026-07-20）以降**: 上記のクレカ伝票キャンセル（B260522012/B260521017/B260521013）は③（`draft-booking-lifecycle`・開始日基準）が稼働していた時期（2026-05）の実証データです。③は #2407 で本番停止したため、現在は③による開始日基準のキャンセルは発生しません。稼働中の自動キャンセルは①（135分・放置カート回収）のみです。

### Shopify Admin での確認結果

2026-05-23 検証: 上記キャンセル伝票の Draft Order GID を直接 Shopify Admin にアクセスして確認したところ、**全て「このアドレスに下書き注文はありません」（404）** が表示されました。Shopify 側で Draft Order が完全削除されており、Backend の `cancellation_reason="Draft Order expired (unpaid)"` と完全に同期しています（重複データなし・データ整合性保たれている）。

## トラブルシューティング

### 「自動キャンセルされていない」と思われる場合

1. **伝票の `source` を確認**
   - `backend_app`（管理画面手動作成）は自動キャンセル対象外。管理画面から手動でキャンセル
   - `cart` は対象になり得る
2. **支払方法・決済性質を確認**
   - 銀行振込は未確定も含めて #1944 で保護
   - 後払い伝票（deferred-checkout）は #2284/#2330 で保護（返却後決済）・自動キャンセルされない
3. **Shopify Draft Order の状態を確認**
   - Shopify 管理画面で該当の下書き注文が請求書送信済みか、正式注文になっているかを確認
4. **自動処理のログを確認**
   - `cleanup-expired-draft-orders` のログと伝票の変更履歴を確認

### 「意図せず自動キャンセルされた」と思われる場合

- カート経由（`source=cart`）の未決済予約が放置された可能性が高い
- 銀行振込の伝票がキャンセルされている場合は、伝票の変更履歴で実行経路を確認
- Shopify Admin の Draft Order ページで履歴確認可能
- 必要に応じて新規 Draft Order を作成して再請求
