## 概要

作成済みの請求書・領収書の一覧表示、ステータス管理、PDF出力を行います。また、複数の請求書を一括で入金処理することも可能です。

### 業務目的

レンタル業務における請求〜入金完了までのライフサイクルを一元管理する画面。以下の業務フローをカバーします。

```
請求書作成 → 顧客へ送信（自動メール）→ 入金確認 → 領収書発行
                          ↓
                    期日超過時：督促メール（自動）
```

### 現行システム（@Suite）との主な違い

| 機能             | 現行（@Suite）    | 新システム                           |
| ---------------- | ----------------- | ------------------------------------ |
| 請求書送信       | 手動メール        | **ステータス変更で自動メール送信**   |
| 督促メール       | 手動              | **期日超過時に自動送信**             |
| 領収書発行       | 別画面・手動      | **請求書画面から直接作成**           |
| 再発行           | 未対応            | **枝番管理（-R{n}）で追跡可能**      |
| ドキュメント種別 | 請求書のみ        | **請求書 / 領収書 / 見積書**         |
| ステータス       | 未入金 / 入金済み | **6段階（未送信〜発行済み + 無効）** |
| 印紙税表示       | なし              | **カラム表示あり**                   |

## アクセス方法

- サイドバーから: **請求・入金 > 請求書・領収書管理**
- URL直接: `/invoices-list`
- 他画面から: 請求書作成完了後のリダイレクト

## 画面構成

### ドキュメント種別

| 種別              | 説明                                               | 作成タイミング                                        |
| ----------------- | -------------------------------------------------- | ----------------------------------------------------- |
| 請求書 (invoice)  | 顧客への請求文書。振込情報・入金期日を記載         | 予約確定後、請求書作成画面から                        |
| 領収書 (receipt)  | 入金確認後に発行する受領証                         | 請求書が「支払済み」になった後                        |

> **注意:** 見積書（estimate）は削除も可能だが、請求書と同じ振込情報・入金期日を持つため、事前提示用途で活用できる。

### ステータスの種類

| ステータス        | 色   | 説明                                               |
| ----------------- | ---- | -------------------------------------------------- |
| 下書き (draft)    | 灰色 | 作成直下、まだ何も処理されていない状態             |
| 未送信 (pending)  | 青色 | 送信準備完了、未送信                               |
| 入金待ち (sent)   | 紫色 | 顧客に送信済み、未入金                             |
| 支払期限超過 (overdue) | オレンジ | 支払期日を超過した未入金の請求書（督促対象）  |
| 支払済み (paid)   | 緑色 | 入金確認済み                                       |
| 発行済み (issued) | 緑色 | 領収書発行済み                                     |
| キャンセル        | 赤色 | キャンセル処理済み                                 |
| 無効 (voided)     | 灰色 | 再発行により旧版として無効化された請求書           |

> **再請求バッジ:** 再発行（reissue_count > 0）の請求書には、ステータス横にオレンジ色の「再請求」バッジが表示されます。

### ステータス遷移フロー

```
[作成]
  │
  ▼
下書き (DRAFT)
  │
  ▼
未送信 (PENDING)
  │
  │ 「送信」ボタン → 自動メール送信
  ▼
入金待ち (SENT)
  │                    │
  │ 期日超過           │ 督促メール（自動）
  │                    ▼
  │              （再送信対応待ち）
  │ 「支払確認」ボタン / 一括入金処理
  ▼
支払済み (PAID)
  │
  │ 「領収書作成」ボタン
  ▼
発行済み (ISSUED)

─── 任意のタイミング ───
  │ 「キャンセル」
  ▼
キャンセル (CANCELLED)

  │ 「再発行」→ 現行版が
  ▼
無効 (VOIDED) ← 新版（-R{n}）が DRAFT で作成される
```

**遷移制約:**

- `VOIDED` からの遷移は不可
- `CANCELLED` からの遷移は不可
- `VOIDED` の請求書は一括入金処理・領収書作成の対象外

## 操作手順

### 手順1: 請求書・領収書の検索

1. 検索条件を入力（キーワード・種別・ステータス・作成日・支払期日）
2. 「検索」ボタンをクリック
3. 検索結果が一覧に表示されます
4. 条件をクリアする場合は「クリア」ボタンをクリック

**期待される結果:**

- 条件に一致する請求書・領収書が表示される
- ページネーションで複数ページを移動可能

### 手順2: 請求書番号からPDFを開く

1. 一覧の「請求書番号」列の青いリンクをクリック
2. 種別に応じてPDFが別タブで開きます
   - 請求書（invoice）: 請求書PDF
   - 領収書（receipt）: 領収書PDF

> **注意（#1208）:** 請求書番号クリックで開くのはPDFです（別タブ）。貸出伝票を開く場合は、伝票番号列のリンクまたは「⋮」メニューの「伝票を開く」を使用してください。請求書番号がない行は「-」表示になりクリックできません。

### 手順3: CSV出力

1. 「CSV出力」ボタンをクリック
2. 現在表示中の一覧がCSVファイルとしてダウンロードされます

**ファイル名:** `請求書一覧_YYYYMMDD.csv`（BOM付きUTF-8）

**出力項目:** 文書番号・種別・顧客名・部署名・請求先担当者・担当スタッフ名・担当スタッフコード・金額・印紙税・支払期日・ステータス・作成日

### 手順4: PDFダウンロード

1. 対象行の「⋮」メニューをクリック
2. 「PDF」を選択
3. PDFファイルが自動的にダウンロードされます

**ファイル名:** `invoice_{請求書ID}.pdf`

### 手順5: ステータス更新

個別のステータス更新は「⋮」メニューから操作します:

#### 送信処理（未送信 → 入金待ち）

1. ステータスが「未送信」の行の「⋮」メニューをクリック
2. 「送信」を選択
3. ステータスが「入金待ち」に変更され、自動メールが送信されます

#### 支払確認（入金待ち → 支払済み）

1. ステータスが「入金待ち」の行の「⋮」メニューをクリック
2. 「支払確認」を選択
3. ステータスが「支払済み」に変更されます

### 手順6: 一括入金処理

複数の請求書をまとめて入金処理:

1. 入金処理対象の請求書を選択（チェックボックス）
   - ※ 支払済み・発行済み・キャンセル・無効の請求書と領収書は選択不可
2. 選択件数が表示されます
3. 「一括入金処理 (N件)」ボタンをクリック
4. 入金日と振込手数料を入力するモーダルが表示されます
5. 入金日（デフォルト: 今日）と振込手数料（デフォルト: 0円）を確認
6. 「入金処理する」ボタンをクリック

**期待される結果:**

- 選択した請求書が「支払済み」に更新される
- 成功メッセージが表示される

### 手順7: 領収書作成

支払済みの請求書から領収書を作成:

1. 画面上部の「領収書作成」ボタンをクリック
   - 自動的にステータス=支払済み、種別=請求書でフィルターされます
   - 対象請求書の「⋮」メニューから「領収書作成」を選択するヒントが表示されます
2. 対象行の「⋮」メニューから「領収書作成」を選択
3. 確認ダイアログで「OK」をクリック

**期待される結果:**

- 領収書が作成される
- 元の請求書のステータスが「発行済み」になる

### 手順8: 再発行

請求書を再発行:

1. 「再発行」ボタンをクリック
2. 確認ダイアログで「OK」をクリック
3. 新しい請求書番号（枝番付き）で再発行されます

**請求書番号の枝番ルール:**

再発行時は元の請求書番号に `-R{回数}` サフィックスを付与する。

| バージョン  | 請求書番号     | ステータス                                        |
| ----------- | -------------- | ------------------------------------------------- |
| 元版        | `I25030001`    | 無効 (voided) ← 再発行時に自動変更                |
| 1回目再発行 | `I25030001-R1` | 通常ステータス（未送信）                          |
| 2回目再発行 | `I25030001-R2` | 通常ステータス（未送信）、`I25030001-R1` は無効化 |

**再発行時の動作:**

- 現行版のステータスが自動で「無効 (voided)」に変更される
- 新版は `reissue_count` を連番として使用し `-R{n}` を付与
- 再発行版PDFには「再発行」の文言が挿入される
- 文書番号カラムにサフィックスがそのまま表示されるため、検索・フィルターも有効

**注意:**

- 旧版は記録として残り、削除されません（監査・証跡対応）
- 「無効」ステータスの請求書は入金処理・領収書作成の対象外

> **Backend対応必要**: `invoices` テーブルへの `voided` ステータス追加、再発行API（`POST /invoice/:id/reissue`）への旧版自動無効化処理追加が必要。MSWモックは実装済み。（iziz-system/ease-rental-frontend#346 参照）

### 手順9: 詳細表示・その他操作

「⋮」メニューから以下の操作も可能です:

| メニュー項目   | 説明                                                       |
| -------------- | ---------------------------------------------------------- |
| PDF            | PDFダウンロード                                            |
| 印刷           | 印刷用PDFを別タブで開く                                    |
| 送信           | 未送信 → 入金待ち（メール自動送信）                        |
| 支払確認       | 入金待ち → 支払済み                                        |
| 領収書作成     | 支払済みの請求書から領収書を作成                           |
| 領収書PDF      | 領収書のPDFダウンロード（領収書のみ表示）                  |
| 支払いURL      | クレジットカード支払いページを別タブで開く                 |
| 再発行         | 新しい請求書番号（枝番付き）で再発行                       |
| キャンセル     | キャンセル処理（取り消し不可）                             |
| 伝票を開く     | 紐付く貸出伝票（`/booking-compact`）を開く                 |

## 自動化機能

### 自動メール送信

ステータス変更に連動してシステムが自動でメールを送信する。手動送信は不要。

| トリガー                            | 送信内容                | 宛先                   |
| ----------------------------------- | ----------------------- | ---------------------- |
| 未送信 → 送信済み（「送信」ボタン） | 請求書メール（PDF添付） | 顧客登録メールアドレス |
| 銀行振込伝票の返却金額 **全件確定**（Issue #2260） | 請求書メール（PDF添付）・自動発行 | 顧客登録メールアドレス |
| 支払期日超過（未入金のまま）        | 督促メール（PDF再添付） | 顧客登録メールアドレス |

> **現行との差異:** 現行システム（@Suite）では担当者が手動でメール送信していた。新システムでは「送信」ボタン1クリックで自動送信される。

### 督促メール

Backendのcronジョブ（`InvoiceReminderCronService`）が毎日自動で処理する。

| 項目           | 設定値                                      | 変更方法                                      |
| -------------- | ------------------------------------------- | --------------------------------------------- |
| 実行時刻       | 毎日 00:00 JST                              | `INVOICE_REMINDER_ENABLED` 環境変数           |
| 督促タイミング | 期日翌日・7日後・10日後                      | `REMINDER_INTERVALS` 環境変数（現行: `1,7,10`） |
| 最大送信回数   | 3回                                         | `REMINDER_MAX_COUNT` 環境変数                 |
| 対象           | 個別請求書 + 統合請求書（銀行振込のみ）     | -                                             |
| 無効化         | `INVOICE_REMINDER_ENABLED=false` で停止可能 | -                                             |

> **クレカ後発料金も督促対象（#2007）:** 返却時の延長料金や追加調整をShopify Draft Order（DO②/③）として送信したクレジットカード伝票も、未入金追跡の対象になります。支払期日（due_date）は請求書作成時に自動計算されます。

> **督促対象の正確な定義（#2244）:** 督促メールの対象は **支払期日を過ぎて請求書ステータスが `SENT`（入金待ち）から `OVERDUE`（期限超過）に遷移した請求書のみ** です（`OVERDUE` は InvoiceStatus の値・PaymentStatus ではありません）。未送信（`PENDING`）や下書き（`DRAFT`）の請求書は督促対象外です。

**督促フロー（現行設定: `REMINDER_INTERVALS=1,7,10`）:**

```
支払期日 → 翌日（1日後）: 1回目督促メール送信
         → 7日後:         2回目督促メール送信
         → 10日後:        3回目督促メール送信（最終）
         → 以降:          手動対応
```

**督促メール件名:**

- 個別請求書: `【再請求】請求書のお支払いについて ({請求書番号})`
- 統合請求書: `【再請求】{年月}分 統合請求書のお支払いについて`

> **注意（Backend要確認）:** コード上のコメントには「09:00 JST」と記載されているが、実際のcron式 `0 0 * * *` は **00:00 JST（深夜0時）** 実行。要確認・修正。（Backend: `src/modules/schedule/invoice-reminder-cron.service.ts`）

## ページネーション

一覧が20件を超える場合、ページネーションが表示されます。

- **前へ**: 前のページへ移動
- **N / M**: 現在のページ/総ページ数
- **次へ**: 次のページへ移動

## 使用APIエンドポイント

| メソッド | エンドポイント                 | 用途                                         |
| -------- | ------------------------------ | -------------------------------------------- |
| `GET`    | `/invoice/list`                | 一覧取得（フィルター・ページネーション対応） |
| `PUT`    | `/invoice/:id/status`          | 個別ステータス更新（送信・支払確認）         |
| `PUT`    | `/invoice/batch-update-status` | 一括ステータス更新（一括入金処理）           |
| `POST`   | `/invoice/generate-pdf`        | PDF生成・ダウンロード                        |
| `POST`   | `/invoice/:id/reissue`         | 再発行（旧版VOIDED化 + 新版DRAFT作成）       |
| `POST`   | `/invoice/:id/create-receipt`  | 領収書作成                                   |

### クエリパラメータ（GET /invoice/list）

| パラメータ       | 型                                   | 説明                                  |
| ---------------- | ------------------------------------ | ------------------------------------- |
| `keyword`        | string                               | 請求書番号・伝票番号・顧客名・担当者名の部分一致検索 |
| `document_type`  | `invoice` \| `receipt` \| `estimate` | 種別フィルター                        |
| `status`         | InvoiceStatus                        | ステータスフィルター                  |
| `start_date`     | YYYY-MM-DD                           | 作成日の開始日                        |
| `end_date`       | YYYY-MM-DD                           | 作成日の終了日                        |
| `due_date_from`  | YYYY-MM-DD                           | 支払期日の開始日                      |
| `due_date_to`    | YYYY-MM-DD                           | 支払期日の終了日                      |
| `page`           | number                               | ページ番号（デフォルト: 1）           |
| `limit`          | number                               | 1ページあたりの件数（デフォルト: 20） |

## コンポーネント構成

**メインファイル:** `src/app/(admin)/invoices-list/page.tsx`（Client Component）

```
InvoicesListPage
├── フィルターセクション
│   ├── キーワード検索（input）
│   ├── 種別セレクト
│   ├── ステータスセレクト
```

**型定義:** `src/types/invoice.ts` の `InvoiceListRowBase` を使用（SSOT）

```typescript
// 表示用に使用する主なフィールド
interface InvoiceListRowBase {
  id: string;
  invoiceNumber: string;        // 例: I25030001, I25030001-R1
  documentType: 'invoice' | 'receipt' | 'estimate';
  customerName: string;
  billingCompanyName?: string;  // 請求先会社名
  department?: string;          // 請求部署
  billingContactName?: string;  // 請求担当者
  totalAmount: number;          // 請求金額
  paidAmount?: number;          // 入金額
  paymentDueDate?: string;      // 支払期日
  paymentStatus?: string;       // 入金ステータス
  status: InvoiceStatus;
  bookingId?: string;           // 紐付く貸出伝票ID
  reissueCount?: number;        // 0 = 原本、1以上 = 再発行版
  createdAt: string;
  // ... その他フィールド
}

type InvoiceStatus = 'draft' | 'pending' | 'sent' | 'paid' | 'issued' | 'cancelled' | 'voided';
```

## 通知・エラー

### 成功メッセージ

| メッセージ                              | タイミング                  |
| --------------------------------------- | --------------------------- |
| ステータスが更新されました              | ステータス変更時            |
| N件の請求書を「支払済み」に更新しました | 一括入金処理時              |
| 領収書を作成しました                    | 領収書作成時                |
| 請求書を再発行しました                  | 再発行時                    |
| 請求書が正常に作成されました            | 画面遷移時（URLパラメータ） |

### エラーメッセージ

| メッセージ                   | 原因           | 対処方法               |
| ---------------------------- | -------------- | ---------------------- |
| ステータス更新に失敗しました | API通信エラー  | 再度実行               |
| 一括更新に失敗しました       | API通信エラー  | 選択内容を確認し再実行 |
| 領収書作成に失敗しました     | 未入金等       | 支払状況を確認         |
| PDF生成に失敗しました        | サーバーエラー | 時間をおいて再実行     |

## 検証チェックリスト

- [ ] 検索条件が正しく反映されている（キーワード・種別・ステータス・作成日・支払期日）
- [ ] 一括処理する請求書が正しく選択されている

- [ ] PDFが正しくダウンロードできる
- [ ] 再発行時に旧版が「無効」ステータスになっている
